# 在线错误分类与恢复整合方案

日期：2026-11-19。状态：用户已于本轮明确批准开始实现；按本设计同步优化 macOS 和 Windows。

## 问题与成功条件

Windows 截图展示 `creation_unconfirmed`、首次原因缺失、最近核验 `network_or_protocol`、累计五次核验。本地 overlay 探针已确认：授权失效、凭据不可读、身份变化、取消和限流都可能被创建核验再次折叠成 `network_or_protocol`。截图不能证明具体是哪一种故障，也不能证明任务一定产生于旧版。

用户要求细分分类，并尽可能完善在线处理与恢复。本文先将“合并方案”解释为统一在线诊断与恢复；正文三方合并的既有行为和安全边界一并覆盖，新的正文合并算法另行细化。后者是否纳入开发范围待用户偏好补充，但不影响本设计的错误分类与恢复契约。

成功条件：用户知道失败发生在哪一步、已确认了什么、系统将如何恢复、何时需要自己处理；短暂故障不会永久挂起任务，结果未知的写入不会产生重复创建、覆盖或删除。macOS 与 Windows 共用原因、策略及状态语义，原生凭据/文件系统/剪贴板适配保留平台差异。

## 当前实现和证据

| 证据 | 实现事实 |
| --- | --- |
| E01 `sync/errors.go` | 多数未知错误被归入网络/协议；未知写入标记与业务原因共用单一错误码 |
| E02 `sync/create_recovery.go` | 创建核验只保留权限、超时、内容不一致，其余原因折叠 |
| E03 `store/create_recovery.go` | 首次原因保留，但最近核验没有完整诊断；所有失败检查计数，三次或十五分钟后进入人工处理 |
| E04 `sync/retry.go` | 已有 2 秒至 5 分钟退避及 RetryAfter；状态保存在进程内，取消也列为短暂故障 |
| E05 `sync/dispatch.go` | 每挂载已有独立公平调度、每文件代次和并发控制，不应另造全局队列 |
| E06 `sync/remote_deletion.go` | 只有成功、完整的原父目录列表可支持缺失判断；失败下载/403/超时不等于删除 |
| E07 `lib/larkcli/runner.go` | 固定 CLI 1.0.99 的结构化协议只提供 type/subtype/code/retryable/retry_after_seconds；没有可靠 HTTP 状态或 request id 字段 |
| E08 本地 ignored overlay 探针 | 已复现 auth_required、credential_unavailable、identity_changed、canceled、rate_limited 在创建核验中变为 network_or_protocol；不是截图根因的现场证明 |

现有默认预算：链接 CLI 20 秒（macOS 原生入口请求 15 秒）；交互恢复 45 秒；后台文档单次处理 90 秒；普通文件传输 20 分钟；调度切片 3 操作/30 秒，并发 3；新保存云端周期 5 分钟。本方案保留新保存周期和既有预算，不通过全局延长超时掩盖错误。

## 目标、非目标与禁止结果

- 覆盖授权、凭据、身份、读取/分页、创建、回读、改名/移动/删除、内容转换和合并、链接、持久化与取消。
- 复用现有操作日志、CAS、代次、云端 token 归属、原父目录证据、非目标 XML/ID 保留校验。
- 首次故障、最近故障、历史缺失原因分别表达；旧日志仍可读，不清空缓存或待上传数据。
- 未知 API/协议/本地错误明确显示“尚未识别”，不能冒充网络故障。
- 不替换同步队列，不增加多选功能，不扩管理员权限，不另建 OAuth/token 刷新实现。
- 不以 `retryable=true`、文件同名、单次 404、应用恢复联网等条件单独授权写入。
- 不根据错误推断远端操作未执行；不将未核实的飞书数字错误码解释成特定含义。

## 功能定义

| 需求 | 触发、输入 | 输出与异常 | 验收 |
| --- | --- | --- | --- |
| R01 统一原因 | 任一在线请求返回错误及结构化事实 | 稳定分类和细分码；无法识别则明确未知 | 同一授权错误在读取、创建核验、链接中同义 |
| R02 标记阶段 | 请求发出、回读、转换、提交等边界 | 操作、阶段、主体范围；旧记录为 unknown | 能区分列父目录失败、读正文失败和改名确认失败 |
| R03 独立结果 | 既有日志中的派发/确认事实 | 未派发、已派发未确认、已核实拒绝、已核实完成 | 原因是授权失败时，已派发未确认仍保留 |
| R04 保留诊断 | 首次/最近失败、恢复成功 | 首次事实、最近事实、最多八条变化记录 | 不用后续原因覆盖首次原因；已解决项不继续标活跃失败 |
| R05 自动恢复 | 可恢复原因且预算、身份和阶段允许 | 等待、只读核验或既有安全写入流程 | 断网/限流不直接耗尽有效核验次数 |
| R06 依赖隔离 | 父目录未上传、单资源无权限 | 等待对应依赖或只阻塞相关对象 | 无关文件继续处理 |
| R07 账户协同 | 同账号请求受限/授权异常 | 共用冷却/授权状态，任务保持各自日志 | 有效限流提示到期前，相关 worker 不再发该桶后续业务请求（已派发除外）；同身份授权入口合并 |
| R08 操作入口 | 用户重新诊断/核验、授权、解决冲突 | 只暴露当前安全动作；请求带最新代次与身份 | 用户修改/账号切换后旧动作失效，不清空历史 |
| R09 兼容与排障 | 历史字段缺失、重启、未知响应 | 缺失标识、诊断编号、受限导出 | 不捏造 HTTP 状态、历史原因或“未发送”证明 |

## 分类矩阵

分类属于原因；“创建结果未知”“等待云端确认”属于操作结果，不能替代原因。

| 原因组 | 细分示例 | 自动策略与人工动作 |
| --- | --- | --- |
| 授权 | 需要登录、授权过期/撤销、应用缺少 scope | 使用既有官方授权入口；同账号核验成功后恢复观察；缺 scope 要明确权限申请 |
| 本机凭据 | 存储被锁、不可访问、凭据缺失 | 提示对应平台凭据存储；可锁定态等待解锁，缺失态要求原账号授权 |
| 身份 | OS 用户、飞书账号、资源所属配置变化 | 停止相关任务；重新绑定/核对身份，禁止替换账号后沿用旧任务 |
| 权限 | 无资源读取权、无写入权、父目录无创建权、本机路径拒绝 | 阻塞相关资源或操作；告知权限类别，不让重复登录代替申请权限 |
| 连接 | 已确认离线、DNS、连接、代理、TLS、超时 | 有证据才细分；短暂失败退避，TLS/代理配置错误显示处理说明，不关闭验证 |
| 服务 | 限流、额度/配额不足、暂时不可用、明确业务拒绝 | 限流遵守等待提示；配额等待恢复或人工处理；明确拒绝不重放不适用请求 |
| 协议 | 非法 JSON、字段缺失、未知返回结构、分页不完整、元数据矛盾 | 保留旧清单与操作结果；有限只读重查，持续不兼容要求诊断/升级 |
| 资源与依赖 | 暂时不可访问、缺失未确认、已确认离开原目录、服务明确删除、移动/改名、父目录待创建 | 按稳定 token/原父目录核验；不按同名绑定、不因无法读取而删除 |
| 转换 | 格式不支持、正文/附件超限、素材缺失、XML/结构解析失败 | 给文件、章节、行号和受限片段；只对可确定的转换规则调整自动重试 |
| 合并与版本 | 本地新代次、远端新版本、内容冲突、定位歧义 | 自动重新读取/规划有界；真实冲突进入复核，保留最新本地内容 |
| 本地持久化/运行环境 | 空间不足、I/O、缓存损坏、数据库忙、驱动不可用 | 明确本机保存和归档状态；禁止云端成功掩盖本地失败 |
| 取消 | 用户主动取消、退出/升级中断、父请求结束、阶段预算耗尽 | 按取消来源处理；用户取消不自动重发，退出保留日志，预算耗尽进入等待/核验 |
| 剪贴板 | 已有新内容、忙碌、不可访问 | 保留新内容，给复制重试提示；不影响文件同步状态 |
| 未识别 | 已知 API 错误但含义未映射、非网络未知错误 | 展示安全码和诊断编号；有限只读诊断，禁止假装网络或自动重放写入 |

`HTTPStatus` 与 `APIErrorCode` 必须分开。当前传输层未可靠提供前者，界面显示“未提供”，不能把错误码 429 或 999xxxxx 自动当成 HTTP 状态。数值错误码只有在已核实映射中才改变策略；其余保留“API 含义未识别”。

## 操作结果与恢复动作

| 结果事实 | 可允许的动作 |
| --- | --- |
| `not_dispatched` | 原因解除后，在现有前置校验和最新任务版本下进入原安全执行流程 |
| `dispatched_unconfirmed` | 只读核验，不直接重发创建/插入/删除/改名；后续动作仍由相应日志状态机授权 |
| `rejected_verified` | 仅明确结构化拒绝且可证明该操作未应用时成立；无法证明则保留未确认 |
| `completed_verified` | 仅按现有精确回读/CAS 规则落库完成；云端成功、本机未落库时继续本地收尾 |

恢复建议为 `wait_backoff / wait_dependency / wait_auth / check_permissions / observe_only / replan / review_conflict / repair_local / retry_copy / inspect_diagnostic`。不能提供一个通用“强制重试写入”动作。

按写入结果限制动作之后，再按身份/权限/本机持久化限制进一步收紧。`ErrUnknownResult` 与 `ErrAuthRequired` 同时出现时，原因显示授权错误、结果保留未确认、动作是原账号授权后只读核验。拆出原因绝不能丢掉错误链中的未知写入事实。

## 阶段与数据

阶段枚举包括：身份检查、授权检查、读取父目录、分页、读取元数据、获取正文、转换、生成合并计划、派发创建、派发写入、回读核验、派发改名/移动/删除、核验命名空间、本地提交、链接查询、剪贴板写入。兼容未知阶段。

统一诊断提议包含：`schema_version / diagnostic_id / operation / phase / cause / outcome / observed_at / attempts / last_success_at / next_action / not_before`，以及可确证且安全的 API 数值码、已知 type/subtype、服务提示等待秒数。首次和最近诊断分别保存；连续相同项合并计数，只在原因/阶段/动作变化时写入最多八条有界历史。

恢复周期另外持久化 `cycle_id / operation_id / intent_hash / policy_version / effective_checks / unclassified_probes / paused_reason / next_due`；沿用原业务操作身份，不能因文件的新保存悄悄重置旧未知操作的预算。

诊断不是业务授权。`outcome` 是既有 journal 的投影，不允许 UI 或策略层更改派发阶段。token、输入 blob、原父目录、generation、checkpoint、逐操作写前快照等证据继续存于现有私有业务记录，不复制进可导出的通用诊断。

仅保留已知 type/subtype 枚举及最多 20 位数字 API 码；未知符号码不得直接写原始文本，归为未知并关联诊断编号。未知 JSON 字段、message、stderr、命令行、URL、凭据和正文不进入在线错误日志。内容转换的位置提示继续用已有受限片段机制，导出默认不带片段或文件路径。

HTTP 状态、request id 当前没有协议保证，不作为本轮必需字段；只有经固定 CLI 协议验证的新增字段才能将来加入。

## 在线恢复规则

1. **断网/限流/服务暂时异常**：每个现有处理预算内最多三次完整逻辑观察尝试（定义见下文）；下一次执行不得早于 `max(服务等待下限, 本地退避) + 非负抖动`。本地退避沿用 2 秒起、上限 5 分钟，抖动 0–20%，不能缩短服务等待下限；不在持有业务锁时睡眠。预算不足时不再启动新请求。
2. **有效核验独立计数**：只有得到完整、合法响应且完成身份/候选验证的观察，才增加有效核验次数。网络失败、授权失败、限流、取消不消耗该次数；保留它们各自的请求失败计数和等待原因。
3. **人工处理阈值**：多候选、内容不一致、身份漂移立即要求复核；连续三次有效完整核验仍找不到目标时进入人工处理。十五分钟未解决仅升级“长期待核验”提示，不能因单纯断网而转成要求重新创建；已有真实歧义不会因恢复联网自动解除。
4. **后台节奏**：新保存仍按五分钟周期；诊断用的只读恢复允许独立到期唤醒，但不派发任何剩余云端写入；观察证据交回正常业务执行器，见下文执行边界。为避免重复尝试，同一 job/代次只有一个在途恢复；重复点击只合并请求，不叠加预算。
5. **恢复后继续**：完整回读证明原写入已执行，则仅确认已完成部分，剩余部分交回正常业务执行器，经过正常周期或单独明确的同步授权、最新身份/代次/原日志校验后才可派发；不重放已经观察到的操作。不证明创建从未发生时，“重新创建”仍需显式确认且原任务保留。
6. **401/授权异常**：只有可信协议/映射支持时才判定授权；复用官方 CLI 与已有登录组件管理授权，按用户域内已验证 canonical IdentityHash 协调，跨 profile/config 的同身份引用共享提示状态。身份不变且核验成功后恢复，不能把网页登录成功当作 CLI 授权成功。
7. **403/404/资源读失败**：错误本身不足以证明删除；调用现有原父目录完整列表与稳定身份核验。分页失败保留旧清单，不作为空目录。原父目录中缺失最多证明资源离开该同步范围，不能据此声称资源已在飞书全局删除；移动去向未知时不追到其他目录再次删除。
8. **转换/协议错误**：输入可确定修正时重新规划；未知响应不能无限重查。同一持久恢复周期三次完整逻辑诊断仍无法识别时暂停并给诊断编号，后台轮次与重启不重置预算；不更换账号、清缓存或用整篇覆盖绕开问题。
9. **局部权限**：只阻塞对应资源/父目录；账户授权变化影响该账户全部相关任务，但不阻塞其他账户。
10. **取消与进程恢复**：用户取消保留“取消”状态，不自启；退出或崩溃重启后从日志恢复观察，不能推断“没收到响应就是没发出去”。本地持久化失败优先处理保存问题，不以云端完成掩盖。

上述服务等待字段取固定 CLI 的 `retry_after_seconds`，不假设获得原 HTTP 头。等待值必须非负且不会溢出 Duration；非负可表示且超过七天时保留真实等待下限并提示长期等待，不能截成五分钟。负数、溢出或非法字段标为协议异常并暂停该目标自动请求，要求重新诊断，不猜测服务等待下限。

## 各操作的整合边界

| 操作 | 自动恢复条件 | 人工边界 |
| --- | --- | --- |
| 新建 | 原父目录完整列表中唯一候选、稳定身份及原提交内容回读通过 | 多候选、内容不同、记录缺失；重新创建是单独授权 |
| 已有文档写回 | 以 Base/Local/Remote 规划，逐操作验证 token/ID/版本/非目标内容 | 重叠修改、定位歧义、远端删除与本地修改并存 |
| 文件上传 | 保留原输入与派发记录，回读对象身份和内容证据 | 未确认上传不能按同名覆盖或重传新建 |
| 改名/移动 | 原 token、源/目标父目录和日志证明原动作已完成或可安全继续 | 位置漂移、同名替代、跨身份资源、证据不足 |
| 删除 | 仅使用原持久父目录证据和原 token；确认已从原同步目录移除则收尾 | 父目录身份变更、列表失败、不能追到新目录再次删除 |
| 目录刷新 | 完整合法分页后替换对应旧快照，其他目录独立 | 失败/部分分页不得清空旧清单或生成删除 |
| 分享链接 | 复用带对象归属的缓存；补查验证身份后 CAS 保存 | 删除重建/账号变化不复用；剪贴板保护只影响复制 |

正文合并沿用现有上下文定位及三方合并：本地与云端互不重叠的可验证修改可自动合并；云端已达到原意图则确认而不再次写入；写入过程中出现新本地代次，旧任务只能确认自己的结果，不覆盖新保存。相同内容的独立表格继续依赖 ID/章节锚点，不用全篇同文匹配猜测目标。

| B01 | `lib/larkcli` 与平台适配 | 可信机器字段、是否启动子进程、超时/取消事实；透传调用方提供的来源 | 不决定重放业务写入；无法细分网络类型时保留未知 transport |
| B02 | 新共用诊断/策略模块 | 统一原因、阶段描述、纯策略建议、字段脱敏 | 不修改 journal/token/代次，不发网络请求 |
| B03 | cloud/sync 执行器 | 标阶段、读取现有结果事实，选择实际安全动作 | 不将格式化用户文案当作策略输入 |
| B04 | store | 原子保存首次/最近诊断、有限历史、预算/到期信息 | 不把诊断迁移变成重排操作或清空未知状态 |
| B05 | 既有 dispatcher | 有界尝试、到期唤醒、公平性、每文件单在途 | 不另造第二套同步队列 |
| B06 | 用户域账户协调 | 跨 worker 的账户冷却/授权提示协调 | 不承诺进程内变量能全局限流，不持有跨进程锁等待网络 |
| B07 | manager/UI | 本机保存/云端结果/当前原因/下一动作分开呈现 | 不根据旧页面快照授权重建或替换原业务状态 |

worker 只上报授权状态，不直接打开登录窗口；已有单实例桌面管理服务按 canonical identity 汇总授权提示并调用既有授权协调器，跨配置引用也不重复请求登录。冷却与提示键使用现有 OS 用户私有域和已验证 IdentityHash（包含 Brand/AppID/UserOpenID）；AuthRef 必须与当前 registry 绑定一致，profile ID 仅作引用和展示。未形成已验证绑定时不派发业务请求，不猜测多个 profile 是同一账号。

跨 worker 冷却是第二阶段能力：在用户域内按上述 canonical identity 与服务桶保存小型记录，受短时用户域文件锁保护并原子替换。记录包含 `identity_hash / auth_ref / event_id / revision / original_delay_seconds / not_before_utc / observed_at_utc / cause`，不存凭据和资源路径。只有真实限流证据可创建或延长等待；更新必须以当前版本 CAS，并取现有有效下限与新下限的较晚值。手动重试、较短新提示、较旧事件不得缩短或清空等待；同一事件的反复读取不会重新启动当前进程的单调计时。新进程保守重新等待原始时长，但不能把本机等待无理由写回延长其他 worker 的全局记录。

每进程请求去重只对本进程生效；现有每挂载并发默认三不伪称全账户总并发三。冷却更新后影响未来请求，不假装撤回已发请求。记录损坏则报告本地状态问题，不能静默重置并放大请求。

## 观察与写入的执行边界

独立到期恢复使用新的云端只读观察接口，只包含身份校验、List、读取文档/元数据和内容观察；接口不提供 Create/Apply/Rename/Move/Delete/Upload。不得直接调用当前会继续派发改名或正文操作的 `syncEntry`、`create` 或完整 `docx` 处理函数。

观察产出带原 operation ID、意图哈希、云端 token、观察前后身份与版本的内部证据。观察器可以记录诊断和观察结果，但不更改业务派发权限。正常业务执行器在 entry/job/代次 CAS 下消费：已完整完成的阶段可仅落库确认；还有任何云端副作用时，交回正常调度和既有前置校验。独立诊断唤醒不允许任何剩余云端写入，也不允许新增文件提前于五分钟周期。

“重新核验/重新诊断”只授权观察，不等同现有 dispatcher 的可写 manual admission。第二阶段必须调整当前 RecoverCreation(recheck) 的 enqueue 链路；显式“立即同步”和“确认重新创建”是不同的业务授权，仍须各自的 CAS、身份及原结果检查。

## 预算、周期和暂停解除

- **Bridge 派发次数**：Bridge 启动一次官方 CLI 命令计一次，含身份检查/分页/正文调用；官方 CLI 内部 HTTP 重试不可观测，不能把该数声称为实际 HTTP 请求总数。
- **逻辑观察尝试**：对一个固定 operation/意图完成身份检查、完整分页、必要正文/元数据和匹配的一次流水线；首次失败即结束。一次逻辑尝试可以有多个 CLI 派发。独立观察预算不超过现有后台 90 秒/交互 45 秒，每个只读阶段不超过 30 秒且受剩余预算限制，最多三次逻辑尝试；重试由这一层统一调度，Bridge 内部不嵌套叠加另一组三次重试。
- **有效核验**：逻辑尝试成功得到完整合法证据并完成检查，才增加 effective_checks；结构矛盾、多候选或内容不符直接转人工。请求超时/授权/限流等不构成有效核验。
- **持久恢复周期**：绑定既有 operation ID、原提交意图哈希和策略版本。重启、五分钟调度和重复点击不更换 cycle_id，不重置 effective_checks 或 unclassified_probes。后台轮次只重新取得受限的执行时间，不解除持久暂停。
- **短暂故障**：本次预算耗尽后进入已持久化 next_due 等待，之后允许同周期再次观察；请求失败计数持续累计并有界/饱和，不能在重启后回到快速重试。
- **持续协议/未知错误**：同周期 unclassified_probes 达三次后持久暂停，只读诊断也不再由每轮 pending 扫描自动解除。仅用户明确“重新诊断一次”带最新 cycle/version CAS，或被验证的 CLI/策略兼容版本发生变化，才可创建新诊断周期；在途重复动作合并。新周期保留旧历史，仍只授权观察。
- **业务歧义**：多候选/内容不符/身份漂移的人工阻塞不会由“重新诊断”或版本变化自动放开写入。新观察可能解释原因，业务决策继续使用现有对应动作与证据。
- **历史计数**：旧总 attempts 原样保留并标“历史累计”；不推断它们属于有效核验还是请求失败。旧人工阻塞保持，用户重新核验可开启新观察周期，新计数从该边界开始，旧计数不覆盖。

## 取消来源的契约

manager/执行器在创建 context 时提供可信来源，使用 WithCancelCause/WithTimeoutCause 或等价内部封装：`user_stop / runtime_shutdown / caller_gone / phase_deadline / parent_deadline / unspecified_cancel`。来源来自受认证的用户动作或实际生命周期边界，不能由客户端任意字符串声明；传输层只报告 ctx.Err、启动事实和透传来源，不推断用户意图。

用户停止按原有挂载/任务暂停语义持久化，须用户继续后才恢复；退出/升级中断保留操作日志，重启先观察；浏览器或 HTTP 调用方离开只取消尚未完成的交互请求，不能撤销已持久接受的后台保存。阶段/父期限归入预算耗尽，不归为用户取消。

没有可信来源的 Canceled 显示“取消来源未记录”：不标为永久用户取消，也不自动放行该操作的云端写入；允许有界只读核验，剩余副作用需显式“继续处理”及正常业务校验。进程崩溃没有取消事件时，保留“中断时原因未记录”，不能事后补造取消原因。

## 数据、权限、兼容与迁移

- 第一阶段仅追加诊断字段与安全 API；旧业务状态、未知派发记录和内容哈希保持。历史首次原因缺失显示“首次原因未记录”，阶段显示“未记录”，不称已确认旧版故障。
- 历史 NeedsAttention 保持；用户重新核验先进行观察，新的诊断决定后续等待或人工提示，不因升级自动放开重建/删除。
- 初始诊断一旦写入不被覆盖；修复/重新授权后更新最近诊断。已解决项保留历史但从活跃错误列表移除；仅全部所需回读与本地落库完成后可显示已同步。
- 单次耗时和进程内服务等待使用单调时钟；本地退避跨重启用 UTC 到期记录。服务给出的等待时长另行持久化，重启时保守重新等待原始时长，再与本地到期信息取较晚值；代价是重启可能延长等待，界面应说明。无法验证系统校时的实际经过时长时不宣称已满足服务下限。
- 同一数据库由既有用户域/worker 锁和安装协调器约束；不支持新旧二进制并发写同一存储。旧客户端可能忽略追加诊断，不能保证降级后的诊断完整，但不会给它新增写入授权。
- 不新增管理员/完整磁盘权限。macOS Keychain、Windows 凭据存储和目录权限分别诊断，禁止笼统申请所有权限。

## 用户可见样例

```text
文件：方案.md
本机：已持久保存
云端：创建结果尚未确认
当前步骤：读取原父目录，查找先前创建的文件
最近原因：用户授权已过期
首次原因：未记录
已完成有效核验：0 次；请求失败：5 次
下一步：使用原账号重新授权，成功后自动核验
操作：检查授权／下载本地副本／复制诊断信息
```

上例是新诊断的展示形状，不是对截图故障的推断。信息不完整时明确显示未记录；不把旧累计五次错误改写成五次有效核验，也不把它强行拆成未知历史数字。按钮由原因与结果共同决定；先前已派发未确认时不提供通用重发按钮。

## 方案取舍与落地顺序

| 选择 | 收益/代价 | 决定 |
| --- | --- | --- |
| A 仅扩充创建错误文案 | 小，见效快；其他入口继续分类分叉，预算问题仍在 | 只作为第一阶段的一部分 |
| B 统一诊断和恢复策略，保留各业务状态机 | 原因一致，可分阶段接入，现有写入证据继续有效 | 推荐提案，由本设计明确接口与边界 |
| C 重写所有同步状态机和队列 | 一致性集中，但迁移和错误重放风险大，扩大当前任务 | 本轮不采用 |

1. **诊断先落地**：共用分类、阶段、首次/最近记录、旧数据标记、界面与复制脱敏诊断、调用方取消来源；优先覆盖截图路径。此阶段保留现有恢复次数策略，不提前宣称网络已可自动恢复；尚未接通的自动动作不能在界面承诺已启用。分类和策略先以兼容/影子方式落库验证，用户可见恢复动作与第二阶段执行器一起启用。
2. **恢复策略接入**：拆有效核验与失败请求预算，区分用户取消，持久化到期信息、账户冷却与授权提示合并；复用现有 dispatcher，逐操作接入并验证。
3. **全链路收敛**：正文回写、命名空间、目录刷新、链接等共用分类/策略；取消旧重复分类出口，增加在线场景故障注入与平台门禁。

上述是实施者提出的默认分期和参数，用户已批准进入编码；本次授权不自动生成发布版本或覆盖现有 0.2.30。

## 验收和真实验证

- **分类**：覆盖每个原因组、复合错误链、未知 numeric/API、错误码不等于 HTTP 状态、不可用字段与脱敏；具体 cause 不得被 unknown outcome 掩盖，反之亦然。
- **创建**：创建成功丢响应、CLI 启动前失败、列表/正文/改名核验分别失败；授权恢复后不得重复创建；保存后新代次保留。
- **恢复**：连续网络失败不计为有效观察；有效完整三次找不到、多个候选、内容不同分别进入正确处理；重启、重复点击、预算、服务等待、抖动、时钟异常无风暴或无限持锁等待。
- **并发**：不同配置/profile 的两个 worker 链接同一已验证身份时共用冷却，较短/旧事件和手动点击不得缩短等待；不同账号继续；单文件失败不阻塞无关文件；同文件同代次无重复在途请求。
- **合并**：远端并发编辑、相同表格不同身份、操作已成功但响应丢失、部分操作完成、未知删除、回读不一致；继续要求非目标内容与 ID 保留。
- **本机/平台**：磁盘满、凭据被锁、权限拒绝、取消、目录清单保留和剪贴板变化分别检查；macOS 与 Windows 的原因语义一致，真实 OS API 另跑。
- **兼容**：旧 `unknown_result`、`network_or_protocol`、缺 FailureCode/phase、历史 NeedsAttention 和历史累计次数不被伪造或重置；损坏诊断字段不能损坏业务日志。
- **真实验证**：只用隔离测试账号/目录、可恢复网络故障和显式授权的写入；不在用户当前问题文档上直接试写。离线 fixture/故障注入、原生 OS 测试与真实账号验收分开记录，不相互替代。

## 依据与设计关卡

设计关卡见 `design-gate.json`。关键契约来自现有代码、实际探针和以下一手资料；不是声称本次 Windows 账号根因已查明。

- [飞书通用错误码](https://open.feishu.cn/document/server-docs/api-call-guide/generic-error-code)：如 99991400 限流，应降低请求频率。
- [飞书 99991672 所需应用权限说明](https://open.feishu.cn/document/faq/trouble-shooting/how-to-fix-the-99991672-error)：缺 scope 与授权过期分开处理。
- [RFC 9110 §9.2.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2)：非幂等写入不能仅凭通信失败自动重发，需可确认的语义/原请求未应用证据。
