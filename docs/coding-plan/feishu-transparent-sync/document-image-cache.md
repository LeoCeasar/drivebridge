# 在线文档与图片一并缓存

用户要求：缓存在线文档时同步缓存关联图片，不等 Typora 渲染时访问云端。

实现边界：目录扫描保持纯元数据；第一次缓存正文、后台刷新正文时先下载全部关联图片，完整写入持久化 blob 后才能接受该版快照。图片下载失败返回可重试错误，保留原版本和所有草稿。图片仍使用现有相对路径；不更改 Markdown 投影或在线块映射。

- [x] 快照增加可选图片 blob 引用，纳入完整性检查、GC 和安全缓存释放。
- [x] 共用文档缓存准备模块，接入首次读取和后台刷新；同文档、同修订的图片复用。
- [x] 旧缓存读取时补齐图片，不修改已有快照或本地待上传内容；图片对象提供已知大小，仅从持久缓存读取。
- [x] 小范围验证失败不发布、重复读取不下载、重启缓存复用、旧草稿不受影响；完成后运行相关模块全量测试和平台构建。

正常路径：获取在线 XML → 生成 MD/资源清单 → 缓存全部图片 → 保存快照 → 发布文档 → 编辑器读取本地图片。

验证：新增文档缓存、图片失败拒绝发布、旧草稿图片补齐、重启离线读取、后台库存补齐、图片读租约保护、安全释放和长期 GC 保护测试通过。internal/bridge 全模块及 VFS/VFS cache 已运行；manager 在首次并行构建负载下出现一次归档超时，独立复跑及后续全模块复跑均通过。macOS cmount 元数据/冷打开测试、Windows amd64 桌面和 Linux amd64 构建通过。已生成 0.1.7 macOS arm64 开发安装包；实机升级至 0.1.7，替换期间 310 个受保护文件哈希不变；目标文档的 4 张图片均在持久化 blob 缓存中存在，挂载读取均可解码 PNG，图片读取约 0.38–1.25 秒；Typora 中原损坏图片已恢复显示。

原生读取兼容：图片预缓存由 ManagedReadPreparer 在路径规范化和读取准入后执行；ManagedOpenValidator 继续只做本地写权限校验。旧快照关联图片在历史 GC、同文档多路径缓存释放时均跟随仍有效的基线保留。
