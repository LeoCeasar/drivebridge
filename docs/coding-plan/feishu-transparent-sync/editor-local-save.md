# 编辑器本机保存与备份改名

实机证据：原《主备更新操作手册.md》的身份被普通改名迁移到《主备更新操作手册~.md》，新文件产生另一身份且无云端 Token/基线，含图片的 Markdown 因新建转换不受支持而阻塞。另有两处保存等待：同目录云端刷新屏障、读写打开时的图片预缓存。

实现：
- 精确识别同目录 `name~.ext` 和 `name.ext~` 两种因果备份，保留原云端 Token、基线和文件身份；备份影子仅在本机保存。默认临时规则增加 `*~`、`*~.*`。
- 备份事务允许保留已有待上传/阻塞/在途任务，不取消或重放它们；覆盖同一份旧备份时仍保留其不可变恢复引用。一般重命名的保护保持原样。
- 已分类的本机备份不等待远端目录刷新；网络获取阶段不持有用于本机提交的元数据锁。
- 图片预缓存仅在只读打开和正文首次物化时执行；读写保存不触发图片预下载，底层已缓存正文读取只访问持久化 blob。
- 已有目录索引时，未命中的文件名直接从本机索引返回不存在，避免为一次新文件检查重新构建所有兄弟文件及图片资源；未初始化的目录仍按原流程加载元数据。
- 本地保存以本机持久化为准；同步失败保持待上传/冲突状态，云端旧快照不能发布覆盖尚未同步的本地代次。不会为清除错误强制采用云端旧版本。

验证：两类备份、连续保存、已有在途代次、重复覆盖备份、阻塞的同目录刷新、断网读写保存；真实 Managed VFS 的多次改名/新建/保存/读取，原身份保持及旧快照拒绝发布；overlay/store/sync/integration/VFS 全模块通过。

2026-11-12 本机升级验收：已安装 0.1.11 unsigned test 开发版，安装替换期间 483 个受保护文件的哈希不变；实际管理页面包含错误面板与本地副本入口。用默认过滤的独立临时测试文件进行三次保存并 fsync、读取校验，耗时分别为 352/215/216ms；两次备份改名为 342/208ms。上版同场景首次保存为 3765ms，此为单机样本，不代表断网、冷文件首次打开或所有编辑器的性能承诺。测试文件已清理，当前挂载正常、无待上传或冲突。
