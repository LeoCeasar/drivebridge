飞书在线文档与本地 Markdown
保留原始结构，按块双向同步

准确结论：带明确内容范围的双向同步可以实现；这次原型证明了样本的读取、资源获取和局部定位，尚未证明整篇 Markdown 或所有复杂内容都能无损双向转换。

核心设计：用户编辑可读的 .md；后台同时保留原始文档、资源身份和块映射；写回时把本地变化翻译成最小块操作，未修改的结构继续留在飞书。格式转换、云端写入、并发正确性分别验收。

本文是实现目标及流程设计。方案三尚未接入正式应用；真实写回、全篇反向解析和多人并发仍需后续验收。既有应用其他功能的历史验收不等于本方案已验收。

2. 总体架构：一个本地文档，后台保留三份上下文

飞书
在线文档与资源

文档身份、版本、块树、文字样式、表格、图片 Token。

↓ 官方 CLI / OpenAPI
获取原始快照

完整范围、身份核验、结构校验、必要时分页。保留原文与资源引用。

本机后台
原始快照 + 投影映射

保存云端结构、投影版本、资源映射，以及分别属于本地和云端的同步基线。

↓ 生成可读内容
本地 Markdown

文字、代码、简单表格；复杂表格保留 HTML，图片使用相对资源路径。

修改返回
编辑器 / AI 保存

VFS 接收 → 本机持久化 → 整篇解析 → 块差异与三方比较。

↓ 只对支持的操作生成补丁
写入一个操作，回读核验

保留非目标结构；获取新版本和块身份后，再规划下一步。

云端回读结果 → 更新投影与确认基线 → 本地看到最终合并内容

用户管理的内容

主备更新操作手册.md

继续使用本地编辑器、AI 和终端，不要求维护块 ID，不要求调用 CLI。

应用管理的状态

原始 XML / 块树、映射、快照、上传账本、冲突草稿、资源缓存。

沿用每用户状态与缓存目录，不将账号信息写进文档。

飞书云盘中的普通 .md 文件仍按普通文件同步；在线文档的 .md 是本地投影。通过资源绑定判断类型，不按扩展名猜测。已有新建 Markdown 策略保持不变：需要创建在线文档时走已配置的创建流程。

3. 在线 → 本地：结构保留，正文不因格式限制消失

读取与刷新流程

目录先显示文件名和基本元数据

目录发现和正文下载分离，保持现有按需读取体验。

↓ 打开、grep 读取，或已有同步策略触发复核
检查正文缓存、账号绑定和版本

缓存可用时复用；正文已清理或需要刷新时，读取云端内容。失败返回明确错误，不返回伪造的空文件。

↓
读取同一版本的原始结构

以完整 XML / 块树为依据。官方 Markdown 可作为辅助结果，只有版本和结构核对通过才采用；不能把不同版本的数据拼接。

↓
逐类型投影，同时建立块映射

可编辑内容生成 Markdown；复杂表格保留结构；未知类型至少提取可解释正文、标题或资源说明，完整原件仍保留。

↓
本地没有待上传内容

持久保存快照与映射，协调 VFS 发布正文。版本变化后更新文件大小和缓存；打开中的句柄按既有保护处理。

本地有未上传修改

不覆盖当前本地正文。保存远端观察，进入三方合并或冲突处理。

↓ 预览器实际读取图片路径时
按需获取图片资源

使用账号鉴权下载到应用缓存。资源不可用时保留引用并显示原因，不把失败解释成图片被删除。

搜索边界：grep 读取投影正文时能找到其中的文字和命令；Markdown / HTML 转义可能改变源码字面表示。需要按原始文本精确搜索时，提供独立纯文本索引；该索引不是写回输入。图片中的文字需要额外 OCR，不能由图片下载成功推导出可检索。

4. 本地 → 在线：差异写回，不把整篇文档重新导入

正常保存与上传流程

编辑器 / AI 保存 Markdown

沿用现有 VFS 稳定写入、关闭句柄及 write-back 策略。原子保存和临时文件改名按现有安全保存机制处理。

↓
先持久保存本地输入和代次

生成不可变快照，记录本次代次 G、对应的本地基线与远端基线。上传前不能将它标记为已同步。

↓
解析整篇本地文件，重建变化范围

通过旧投影、块上下文、父子结构和内容差异定位；不能只靠行号，也不能只按相同文字匹配。

↓
所有变化可解释且可写

继续计划最小操作。未改变的复杂块继续保持在服务端。

未知语法、结构变化或定位歧义

保存完整草稿并暂停本篇写回，显示具体问题位置。首版不先写入半篇支持内容。

↓ 可继续时
获取最新云端 R，进行三方比较

比较上次同步上下文 B、本次本地输入 L、最新云端 R。只有本地变化则规划补丁；云端也变化时执行合并规则。

↓ 计划无冲突且操作能力已验证
写前复核，持久记录操作意图

校验目标块、原内容指纹和最新身份；持久记录 before / desired、操作目标和发送状态。检测变化则重规划。

↓
执行一个块操作

复用现有官方 CLI 传输层。现有适配包含块替换、插入和删除；需要更细粒度文字更新时单独增加并验明契约。

↓ 重新获取远端结构
读回能确认预期效果

核验目标与需要保留的上下文，记录结果。若还有操作，用本次回读的新版本和新块 ID 重规划。

超时 / 结果未知 / 读回不符

保留本地输入、基线与账本；进入复核或人工处理。不能直接重放已发出的变更。

↓ 全部操作确认
提交远端确认与本地投影

持久记录实际远端结果，协调本地发布。只有本地代次仍与候选结果一致时更新正文；后来新输入保留并进入下一轮。

并发限制已在既有项目设计中确认：当前接口的版本参数不能当作服务端 If-Match / CAS。写前复核与写后读回只能缩小窗口、发现部分异常，不能保证阻止所有网页端覆盖，也不能保证恢复从未观察到的中间版本。方案沿用“尽力检测、合并和恢复”，不承诺强一致协同。

5. 表格、图片和代码块能做到什么程度

下表区分“本次事实”和“正式实现目标”。第一阶段优先满足当前操作手册；没有完成真实写回验收的类型，保持能力关闭。

内容在线 → 本地设计本地 → 在线设计当前证明程度 / 发布边界
普通段落、标题、列表正常 Markdown，保留文本及层级准确映射时更新、插入或删除对应块；插入顺序和父子关系明确样本正文可读，纯文本段落可离线模拟；整篇反向解析和真实写入待验收
标准代码块代码围栏 + 语言；保留空格、Tab、换行和字面符号；不对代码正文通用反转义修改代码正文或受支持语言字段；保留原块其他信息，回读逐项核验构造样例读取通过；需要真实多语言代码文档验证双向流程
当前手册中的表格保留 HTML 表格与单元格内多段文字；不擅自判定为代码块优先只修改单元格内目标段落，保持表格结构6 表格读取通过；单段本地 XML 修改通过；云端嵌套段落操作待验证
简单矩形表格满足条件时用 GFM 表格，否则用 HTML先支持已有单元格文字；新建简单表格需单独验收不能因普通表格已支持，就默认支持所有表格转换
合并单元格、多行列、嵌套布局保留可解释结构和完整文字；必要时提供专用预览第一阶段禁止结构增删、合并拆分和跨单元格移动；准确定位的内部文字能力分批打开本次样本未覆盖；需要独立真实样本
图片相对路径引用 + 鉴权按需下载 + 本地缓存未修改图片保留；新增、替换、删除通过独立资源操作，并确认文档绑定4 张真实图片读取通过；资源写入第一阶段关闭，后续再开放
粗体、颜色、下划线等正文始终可读；Markdown 支持的样式投影，其他样式留在原始结构先只做能明确保留样式的文本修改；跨多个样式边界的变更不能猜测继承规则6 个样本富文本段落当前只读；原型不支持其模拟修改
公式、Mermaid、画板、附件可获取源码时展示源码，其他内容保留说明、资源与原文入口每种类型使用专门适配；没有验证时禁止反向重建“能看到”与“能完整编辑”分开，不由普通代码块能力推导
内嵌 Sheet / Base / 动态组件明确资源类型、可用摘要和在线入口，原件保留不把它们转成普通 Markdown 后覆盖原对象不纳入第一阶段双向编辑

HTML 表格并非所有 Markdown 编辑器都能一致渲染；应用预览页负责提供可控的阅读效果。本地仍可直接编辑源码和检索正文。

6. 双向转换依赖什么数据

不能只保存一份 Markdown 再试图还原全部飞书结构。映射和原件必须在首次投影时一起持久保存，编辑器改写后才有可靠的比较依据。

状态必须保存的信息用途
文档绑定profile / entry / 远端资源身份 / 账号绑定相同文件名不代表同一文档，禁止跨账号复用映射
原始快照完整 XML / 原始块数据、revision、不可变 blob 引用保留未投影的信息及恢复上下文
投影映射投影版本、本地块 ID、当前远端 ID、父块、子结构、多个 UTF-8 字节范围、原内容指纹、可读 / 可写能力支持一个表格对应多个单元格和多个 Markdown 范围
资源映射稳定本地资源 ID、原文资源 Token、来源版本、本地相对路径、缓存状态、已知 hash / 大小图片路径不承担远端身份，也不保存登录凭据
两端基线LocalCheckpoint、RemoteCheckpoint 及其投影关联本地输入和云端回读可能因合并而不同，不能合并成一份含糊的基线
本地代次与账本generation、操作前快照、目标变更、发送状态、读回结果、冲突草稿处理上传期间继续编辑、进程重启和请求结果未知

精确定位规则

  1. 先比较基线和当前本地解析树，确定哪些内容被修改；格式化造成的行号变化不直接等于云端结构变化。
  2. 使用父子结构、邻接块、内容指纹和已有本地身份共同定位。重复文字、复制粘贴或大范围移动导致歧义时停止自动写回。
  3. 远端块 ID 只属于取得它的最新上下文；替换后可能改变。每次写入回读后更新映射，不将它当作永远稳定的本地 ID。
  4. 未改动的未知块不重发、不重新导入。原始 reference_map 用于解释原件，不能整份盲目重放。
  5. 空段落是实际结构；标题、换行和表格内段落边界不能因为显示上“不重要”而自动删除。

只有本地变化在能力与映射明确的前提下直接计划写回，不要求人工确认
只有云端变化，本地干净更新本地投影；不能覆盖打开中的脏缓存

8. 图片不是一个永久 URL：资源身份与缓存单独管理

图片读取与后续替换

原文资源引用

文档版本 + 图片 Token → 稳定本地资源 ID。原始 alt 说明保留，不等同于 OCR。

本地相对路径

Markdown 引用虚拟资源路径；应用内部映射至缓存与鉴权请求，凭据不进入文档。

实际读取时下载

先写临时文件，检查成功状态、格式及可得大小信息，再原子发布。失败保留旧安全缓存和错误状态。

后续图片替换：本地新资源 → 上传并确认资源 → 绑定目标块 → 文档回读确认 → 提交映射
  • 建议使用每个目录下的隐藏虚拟资源路径，例如 .drivebridge-assets/<本地文档ID>/image1.png。这是设计选择，尚未实现；远端 Token 不直接作为可见目录名。
  • 资源实体保存在应用缓存；虚拟路径保证编辑器可以读取。隐藏资源由专门路由处理，不作为用户新文件再次上传，也不进入普通排除规则的误删逻辑。
  • 图片新增 / 替换第一阶段关闭。开放后必须验证上传结果、目标绑定和回读；上传超时不得盲目再建资源。
  • 沿用用户确认的清理策略：7 天未使用或超过容量时优先清理最久未使用的已同步正文；待上传资源、冲突引用和正在使用的资源不清理。
  • 临时下载 URL 过期后重新获取，不写成文档的永久资源地址。编辑 Markdown 中的外部图片 URL 不自动等于已获准下载并上传该资源。

9. 用户使用流程

沿用应用登录→自动挂载账号盘→看到个人 / 共享目录→打开文档或 AI 读取→本地编辑并保存→后台同步 / 必要时提示

本方案不增加账号登录步骤，不要求用户选择转换命令。账号盘、目录发现和平台后台运行沿用既有实现；不会因新增文档适配而重新实现挂载驱动。

日常操作用户感知后台行为
查看目录始终能看到已发现的文件名刷新目录元数据，不先下载整个云盘
打开文档 / grep 读取获得实际正文，必要时等待加载提供可用缓存或获取最新需要的正文；失败给出错误
预览图片图片按需出现独立鉴权下载并缓存；不让正文因为图片失败整体消失
保存支持的修改正常保存；托盘显示待上传 / 已确认状态先本地持久化，再执行差异与云端核验
修改不支持的内容草稿保留，明确指出具体限制暂停本篇写回，保留远端原件
发生可检测冲突托盘计数增加，打开三方 diff保存多方快照，处理后基于最新云端重新规划

10. 状态、失败恢复与升级

本机已保存→等待同步→读取与合并→发送操作→等待回读→云端已确认

旁路状态：需要合并、内容暂不支持、网络 / 权限阻塞、操作结果未知、本地发布待完成。它们不能被统一显示成“已同步”。

  • 网络与权限失败：保留原文、缓存和本地草稿；失败不构成远端删除证据。未发送的请求可按分类重试，已发出的不确定变更进入复核。
  • 连续多次本地保存：确认旧作业时不清理新代次；只有与投影候选一致的代次才能发布，防止“上传成功”覆盖刚写入的更新。
  • 多操作中断：每步持久记录回读结果，重启后先核实未确认操作。不能把剩余计划建立在旧块 ID 上。
  • 投影升级：增加 codecVersion 和侧车格式版本。干净文档可重新投影；脏文档保留旧基线和旧解释规则，不能静默用新投影替换它的比较基线。
  • 清理缓存：只有确认无待上传、无冲突引用且不在使用中的正文可淘汰；升级不清空同步账本。
  • 预览与脚本：复杂内容走受控渲染，保留可读信息；不直接执行远端嵌入脚本，不因预览加载任意外部资源。

建议按四块实施

  1. 读取补齐：正文、真实代码块、当前手册表格、图片按需读取；先消除不必要的整块占位。保留旧写回限制，不提前放开未适配写入。
  2. 整篇反向差异：编辑器实际改写 Markdown 后，正确识别多个独立变化、格式化、重复段落、表格嵌套及不支持区域；先只生成本地计划。
  3. 支持类型真实写回：在独立测试文档中验证普通文字、标准代码、表格内文字的逐步操作、回读及两端显示；每类单独开放能力。
  4. 协作、资源写入与恢复：双账号并发、超时结果未知、上传期间继续编辑、投影升级及缓存恢复；图片新增替换另列一批验收。

验证遵循当前用户偏好：每个分块做有意义的小范围检查，模块完成后运行受影响模块的完整检查；不重复运行已验收且未受影响的安装、登录或其他平台流程。
