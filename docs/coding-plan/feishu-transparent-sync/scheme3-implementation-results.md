# 方案三首批实现与验证记录

日期：2026-11-12。设计：[scheme3-design.html](scheme3-design.html)。本文记录产品代码的实际结果，替代仅凭离线预览判断可行性的结论；不把首批能力解释为所有内容无损往返。

## 已接入的行为

- 默认使用 v2 可读投影：复杂表格、多段单元格、空段落和富文本的可解释正文不再统一替换为 Unsupported。原始 XML 保留在不可变快照中。
- 图片投影为 `.drivebridge-assets/<资源摘要>.<后缀>`；同目录只读虚拟资源从当前文档已接受的侧车及原始 XML 共同授权。列目录和对象查询不下载图片，实际读取经过托管账号和受控临时文件。
- 素材下载处理官方 CLI 自动补文件扩展名的行为，验证结果路径、大小、文件身份、图片类型及完整性。读取关闭或取消时释放临时文件。当前支持受验明的光栅图片，64 MiB 上限；SVG 等未支持格式明确失败。
- 整篇 Markdown 解析后，生成支持内容的局部操作。支持混合文档中普通段落、标题、代码的修改和明确的顶层增删，以及复杂表格内纯文本段落修改。保留其他内容；多步变更每次读回后重新定位，不沿用失效块 ID。
- 本地和云端独立节点的变化可以合并，同节点不相容变化报告 overlapping_edits。结构、样式或资源变更未受支持时，完整草稿和零操作一起返回，不先写入“半篇”。
- 版本化侧车保存 ProjectionVersion、Assets 和嵌套块信息。旧侧车缺少版本时按 v1 重建并核对持久 Markdown；旧未上传作业与冲突继续使用 v1。干净文档允许在云端 revision 未变时升级投影。
- 管理页区分无法安全写回的结构和映射歧义，保留草稿；人工合并仍须经过安全计划器。

本地原型先前下载并显示了 4 张图片；本轮正式素材适配器的真实传输验明使用其中一张，不将两种证据混同。

## 真实云端写回证据

在既有 `模型部署共享文件夹/test` 中新建专用文档 `DriveBridge-Scheme3-验证-20261112-162539`。仅该受控文档接受本轮写入，用户原手册和其他已有文档未修改。

使用当前产品同步引擎、持久 Store、cloud.Client 和托管官方 CLI，而非直接字符串替换服务器响应，依次执行：

1. 普通正文 `scheme3 intro` → `scheme3 intro updated`。
2. 表格内段落 `cat app/.env` → `cat app/.env.local`。
3. 标准 Bash 代码 `echo hi` → `echo scheme3`。

云端版本从 3 到 6，作业状态 `synced`，Store.Validate 通过。每次替换后的目标块 ID 发生变化，后续步骤仍能重新规划。读回保留同一表格身份、列宽、单元格属性、未修改的 `git log` 与尾段，以及代码块 caption / wrap / lang 信息。

CLI：官方 v1.0.99，VCS `8d8357d39dd15ac5e9aa815d4ab2639d56bd3239`；实际安装的 darwin/arm64 二进制 SHA-256：`a8f652c2a62577a152467a983ec60548570fb0a08715e95fa3f579438c81885b`，匹配现有信任固定值。仅在隔离测试实例授予的操作能力下验证；运行时继续以固定二进制与证据决定能力，不读取用户可编辑授权声明。

含云端资源身份的原始请求、响应和临时探针保留在 Git 忽略的 `.superpowers/scheme3-live/`、`.superpowers/scheme3-media-live/`。不把真实文档原件、账号、凭据或资源 Token 提交仓库。

## 自动检查

各模块先跑相关失败回归，再完成受影响模块检查：

- `lib/larkcli`、`internal/bridge/cloud` 完整模块通过；自动图片后缀回归与取消清理竞态检查通过。
- `internal/bridge/markdown` 完整模块通过；额外回归覆盖显式合并兼容、顶层增删、独立远端插入、同段冲突原因。
- `internal/bridge/overlay` 完整模块通过；真实托管 VFS 生命周期覆盖资源读取、缓存命中与撤销引用，伪造 / 跨目录 / 遍历路径和只读操作保护。
- `internal/bridge/sync`、`integration`、`manager`、`ui`、`model` 受影响完整模块通过。引擎回归覆盖旧投影、干净迁移、旧草稿 / 冲突、混合多步骤写回、不同节点并发、未知结果回读、结构错误不部分写入。
- macOS 原生 `desktop,cmount`、Windows amd64 桌面与 Linux amd64 CLI 编译通过。交叉编译不等同于 Windows/Linux 实机安装和挂载验收。

## 明确保留的边界

- 图片新增 / 替换 / 删除、表格行列结构变化、合并拆分、富文本样式重建以及动态组件写回不开放。可以读取的文字不等于可以任意修改结构。
- BaseLocal 与 BaseRemote 的结构分歧无法明确对应、重复内容的映射歧义等情况保留草稿并停止自动写回。
- 本轮没有双真实账号同时编辑的验收；并发逻辑由模拟 provider 回归覆盖。服务端版本参数仍不是原子条件写，不承诺消除最后检查与写入之间的覆盖窗口。
- 首次经 VFS 打开一张冷图片，当前会获取一次尺寸，再下载一次用于缓存填充；后续打开复用 VFS 缓存。这是现有接口下的性能限制，不影响目录列举按需行为，后续可优化租约交接。
- 正式应用升级和安装包版本以实际安装 / 构建结果为准；不能从源码实现或此记录推断当前运行进程已切换。
