| ID | 决定 | 确认来源 |
|---|---|---|
| R-01 | 人和 AI 只编辑本地路径；同步、转换和调用 CLI/API 全部在后台完成 | 用户明确纠正 CLI 为内部实现细节 |

| R-03 | 指定协作目录中的新建 `.md` 默认对应飞书新版在线文档；不自动转换已有普通 `.md` 资源 | 用户对该具体提议答复“好的” |

| R-05 | 其他普通文件先整文件覆盖，不实现内容级合并 | 用户最新范围收敛 |
| R-06 | 无法自动合并时保留本地冲突副本、弹窗提醒，提供 diff 界面辅助人工合并 | 用户明确要求 |
| R-07 | 首版保存后数秒内自动同步，不要求逐字实时协同 | 用户答复“可以” |
| R-08 | 保留原始目标：Rclone VFS、共享目录按需访问、跨平台 CLI、可选桌面组件、多账号、缓存恢复和安全停止 | 最初 v1.0 设计；后续未撤销 |
| R-09 | 每个用户在自己的电脑上独立配置账号、共享目录、挂载点与缓存；配置按系统用户和 profile 隔离，路径从当前系统用户目录动态确定；实验路径与账号不得写死进产品或安装包 | 用户在测试授权过程中明确补充多人多电脑部署要求 |
| R-10 | 用户在查看真实接口反例后，接受首版尽力合并、已取得版本/本地备份辅助恢复及冲突弹窗/diff；网页和本地同段并发仍可能发生覆盖 | 用户最新答复“可以” |

“数秒”是目标体验，不是 API 限流、网络故障或大量文件同时修改时的硬实时承诺。具体默认参数、Markdown 语法范围及界面载体已作为工程决定写入正式设计，供用户审阅。

用户选择的“其他文件覆盖”不等于允许上传失败时删除本地数据，也不等于允许先删旧远端再创建新资源。非 Markdown 文件的并发覆盖不承诺内容合并或版本隔离。

## 外部证据及其边界

- 官方 CLI [Markdown 说明](https://github.com/larksuite/cli/blob/main/skills/lark-markdown/SKILL.md)：普通 `.md` 与在线 docx 是不同资源；`markdown +patch` 是下载、本地替换、整文件覆盖，不是服务端原子 patch。
- 官方 CLI [在线文档编辑说明](https://github.com/larksuite/cli/blob/main/skills/lark-doc/references/lark-doc-update.md)：支持按块修改、基准版本和回读验证；可能返回部分成功。参数存在不等于服务端具备 compare-and-swap 语义。
- 官方 CLI [更新源码](https://github.com/larksuite/cli/blob/main/shortcuts/doc/docs_update_v2.go)：当前 `docs +update` 经 `docs_ai/v1/documents` 提交基准 `revision_id`；不能将该契约与 `docx/v1/.../blocks` 的版本字段混为一谈。
- 官方 CLI [Markdown 映射说明](https://github.com/larksuite/cli/blob/main/skills/lark-doc/references/lark-doc-md.md)：存在转义规则与非原生 Markdown 块，不能默认导出再导入可以完整保真。
- 官方仓库 [Issue #1093](https://github.com/larksuite/cli/issues/1093#issuecomment-4537872062)：报告者提供了过期 revision 仍成功写入的实验。属于一手问题报告，并非维护者保证，也不是本项目实测；当前不能据此承诺绝对无损并发写入。
- 上述链接指向可变 main 或 issue；正式实现前须固定 CLI 发布版本、源码提交、平台架构和响应样本。
