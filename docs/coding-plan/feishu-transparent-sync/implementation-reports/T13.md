## Store API and behavior

```go
var ErrConflictCopyChanged error

type ConflictCopies struct {
    Directory, Base, Local, Remote, Draft, Manifest string
}
type ConflictCopyFile struct {
    Role, Name string
    Blob model.BlobID
    SHA256 string
    Size int64
    Available bool
}
type ConflictCopyManifest struct {
    SchemaVersion int
    ConflictID model.ConflictID
    EntryID model.EntryID
    Generation uint64
    RemoteRevision string
    Kind model.Kind
    Files []ConflictCopyFile
}
func (*store.Store) ExportConflictCopies(context.Context, model.ConflictID) (store.ConflictCopies, error)
```

- Uses only a canonical conflict UUID and captured Store conflict/blob references. Creates private `state/conflicts/<UUID>/<descriptor-SHA256>/` files, four named roles where actually observed, and a relative-name SHA/count manifest. Docx uses `.md`; ordinary files use a small safe extension allowlist or `.bin`. No cloud URLs, CLI output or credentials are added.
- An unavailable base/remote/draft has `Available:false` and no returned path. A genuinely empty local blob creates a genuine zero-byte file. Blob data is streamed under ReadBlob leases and verified, never linked to writable human copies.
- Cross-process per-conflict lock, stage directory, file fsync, atomic manifest rename, directory sync, atomic version-directory publish and hierarchy sync. Errors retain source blobs/queue. A post-publish sync error can return paths plus error so the caller does not pretend nothing was written.
- Same descriptor is idempotent after reopen. Modified/symlinked existing managed copies are rejected with `ErrConflictCopyChanged` and remain untouched. Changed draft/content/revision creates a new immutable version, preserving previous edits. Existing user files are never overwritten. T09 owns intentional CLI/GUI exposure and native notification composition.
