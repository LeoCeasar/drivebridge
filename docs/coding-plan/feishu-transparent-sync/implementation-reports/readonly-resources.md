# T05 compatibility follow-up: read-only online resources

Commit **75b275004**, branch `feature/feishu-readonly-resources`, worktree `/4351/drivebridge`. Owns only `internal/bridge/overlay/**` and the additive `Metadata`/`Observation`/`ObserveEntry` handling in `internal/bridge/store/store.go`. No model enum, manager/UI/packaging or other store file edits. Report remains ignored/uncommitted.

## Result

A complete directory listing containing sheet, bitable, wiki, legacy doc or another nonempty unsupported provider type no longer fails solely because of that type. Native Docx remains KindDocx/Markdown. Uploaded files, including `.xlsx` and `.docx`, remain ordinary writable KindFile objects. Unsupported online resources use KindFile plus persisted `Metadata.VirtualType` and are generated read-only objects; there is no spreadsheet/bitable/legacy-document conversion.

- The provider's actual validated HTTPS URL becomes `[InternetShortcut]\r\nURL=...\r\n`, named `.url`. Missing/invalid URL becomes `.unsupported.txt` explaining the escaped resource type. No tenant/token-derived URL, content execution, remote body download or invented metadata.
- URL validation rejects userinfo, control/whitespace/newline injection, backslashes, and percent-encoded controls/backslashes. Unsafe URLs are not emitted. A later invalid/missing URL clears the previously persisted URL; existing object handles retain their captured safe bytes.
- Filename collision handling uses the existing normalized, token-hashed mapping. Entry remote, token and ID survive reopen and source metadata refresh. A raw uploaded `raw.url` cannot be overwritten by an online resource named `raw`.
- `NewObject` and `MaterializeManaged` reconstruct the generated bytes from persisted metadata. Size and SHA256 describe the captured bytes, byte ranges work, and Storable is false. No blob import, Stage, pending job, body observation or document fetch is performed. `ShouldSync` and active-entry filtering exclude virtual resources.
- Update, Put-to-existing, SetModTime, Remove, Mkdir-on-virtual, Move, rename source, atomic replacement target, and direct publication reject with `fs.ErrorPermissionDenied`. Begin checks the target before allocating an unseen cached source. Complete-list classification and namespace preparation share the existing list exclusion, closing the new-virtual-target replacement race. RenameManaged rechecks persisted prepared paths before sealing/committing. Denials leave no new namespace freeze or virtual generation/content mutation.
- `Rmdir` includes generated resources in List and rejects nonempty folders, including a folder whose only child is an unknown future online type. Nothing is silently hidden to enable folder deletion. Parent separately owns the engine's fresh remote-folder emptiness check.
- Store metadata is additive (`virtual_type,omitempty`). Only token-bearing observed KindFile entries can be introduced as virtual; local creation cannot set the flag. Existing token/type classifications cannot be rebound or cleared, including ordinary pending local entries. This is a conservative identity error on a provider changing an already-bound type, not a silent format change.
