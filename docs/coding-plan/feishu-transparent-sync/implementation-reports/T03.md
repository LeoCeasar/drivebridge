## Durable behavior

- Real bbolt v1.4.3, schema version 1, private directory/file helpers and exclusive flock. Baseline buckets plus snapshots/metadata/publications. Unknown schema rejected. Open preserves directory entries; blob acceptance follows copy/hash, file sync, close, atomic replacement, directory sync, then a short database transaction. Failed transactions leave only unaccepted orphan blobs.
- Open alone does not authorize reads/writes: BindScope verifies canonical non-nil UUIDs and immutable mount/profile/remote/identity/root resource binding. Mismatch returns model.ErrIdentityChanged. On first binding after reopen, interrupted merging/uploading work becomes awaiting_verification and prepared creates become unknown; no automatic cloud retry.
- EnsureEntry/list discovery creates unmaterialized paused entries without jobs. ObserveEntry atomically attaches resource metadata, preserves FirstObserved and fallback ModTime once, preserves opaque SourceURL, rejects changed token/kind and refuses to bind a tokenless pending local creation through discovery.
- Stage durably accepts bytes and increments generation. Prepare is atomic per entry, waits for prior pending generations or other inflight work with context cancellation, checks scheduling freeze, and rebinds both accepted checkpoints at prepare time. Pending sorts by entry/generation. Unknown jobs cannot Prepare again.
- Confirm advances accepted captured local/cloud baselines only, preserving newer generation bytes/status (including a newer conflict). Publication candidates are durable. CommitPublication requires the exact persisted candidate, expected generation and remote checkpoint, an unfrozen entry and no pending upload. PendingPublications resumes accepted local publication across restart.
- SaveFileSnapshot verifies typed FileIdentity, actual SHA-256 and byte count, stores ordinary bytes only in FileData, and never fabricates Revision. Save and adoption are distinct. Adoption requires initial clean/unmaterialized, non-tombstoned, unfrozen matching generation/token; refresh uses OfferRemote and upload verification uses Confirm. OfferRemote cannot publish ordinary bytes different from the saved snapshot. ProtectBackup durably binds existing same-resource evidence to an existing job.
- Namespace kinds are `rename`, `replace`, `delete`, `mkdir`. Root remote is empty string; root deletion and unsafe/traversal paths are rejected. Prepare freezes the source/destination tree and scheduling. Stage remains permitted during prepared freeze for Flush. Seal captures latest durable generations and closes staging. Commit validates those generations and atomically updates index/tombstones/content. Replace retains destination EntryID/token, increments its generation, keeps prior contents recoverable, and never deletes destination identity. Source inflight/unknown blocks; destination inflight G1 may confirm across replacement. Finish unfreezes; committed journals cannot Abort. Abort before commit preserves accepted Flush bytes. PendingNamespace replays unfinished local transitions.
- NamespaceActions exposes durable external mutation intents only after Finish; AcknowledgeNamespaceAction clears the pending intent after the engine reconciles its result. These methods do not perform network requests. Queued content jobs superseded by replacement/delete stay recoverable but are excluded from dispatch.
- Create journal saves input and a UUID-based unique temporary name before a request can be dispatched by its caller. Unknown survives restart. BindCreated is idempotent and token/revision-safe, including newer local generations; FinishCreate never marks unobserved bytes synced.
- Conflict inputs/drafts and plan/result journals persist. Resolve checks captured generation/revision and atomically stages a new generation. Backup emits a consistent bbolt database image.

Default large snapshot threshold: 10 MiB inclusive. Default admission calls real disk.UsageWithContext and rejects additional large snapshots if free space falls below 1 GiB, with ErrSpace. It never removes accepted data. Ordinary files have no 10 MiB maximum; Docx staged/resolved content does. Unreferenced prepared blobs receive 24h grace. Snapshots retain latest ten per resource token OR anything within 30 days; explicit references override expiry. GC marks FileData and all live entry checkpoints, job inputs/bases/plans/desired, conflict/draft, namespace/create/recovery, valid publication and active read leases. Stale publication intents are pruned without deleting referenced data. Terminal job history outside ten/30d can be pruned. The 5 GiB default is advisory; OverBudget never overrides protected references.

## Limits and integration responsibilities

No network, server CAS, historical server-version guarantee, CLI/account action, or native disk-full proof is claimed. File confirmation presumes the engine has verified the observed uploaded bytes; Store validates typed immutable evidence and journal transitions, not request causality. OS fsync/write errors propagate. Windows directory durability uses the existing platform helper's write-through replacement semantics; only the local macOS package was executed here.

Recovery/conflict/namespace/create references are conservatively retained without automatic expiry; queue acceptance and protected content can exceed 5 GiB. Backup writes only a consistent database image; a complete offline backup must also copy the immutable blob tree while quiesced. Network namespace action reconciliation, materializer/VFS barriers, retention UI and releasing long-lived recovery intent are downstream responsibilities. No missing required canonical model change was found.
