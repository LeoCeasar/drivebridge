## Implemented behavior

- Internal fs.Fs constructor requires the already-bound Store and matching ProfileID/MountID, plus concrete Cloud or a narrow read-only Source. It does not register a backend or read global rclone configuration. Existing native feishu uploads remain unchanged.
- List acquires one complete Source.List metadata result, validates every row before binding observations, and merges local entries. It does not fetch document/file bodies. It maintains stable Entry.Remote/CloudName mappings, reuses EntryByToken across renames, and excludes tombstoned resources even if the remote list is stale. Missing cloud rows do not infer deletion; authoritative remote deletion/conflict processing belongs to engine.
- NewObject and list objects report Size=-1 while unmaterialized. MaterializeManaged resolves only the requested object, coalesces concurrent acquisition per EntryID, and does not refresh already-materialized content. Ordinary files use owned ObserveFile leases, verify declared size against Store.SaveFileSnapshot actual bytes/hash/typed identity, then initial clean adoption. Files never put binary data in XML/Markdown or fabricate revision.
- Document materialization uses actual markdown.DecodeWithOptions, keeps the provided source URL/reference map, saves immutable XML/Markdown/model.DocSidecar blobs, and publishes the initial previously-unexposed projection through OfferRemote/CommitPublication. Revision is required. Later remote refresh must use engine PublisherVFS -> overlay.Publish; MaterializeManaged cannot bypass that barrier for an existing materialized object.
- fs.Object captures a visible BlobID and exact byte size. Open/Range/Seek read that same immutable leased blob, clamp ranges, reject invalid/multiple mandatory ranges, and propagate cancellation/errors. A previously returned object continues reading its captured snapshot after another object is published. Hash exposes SHA-256 of captured content; metadata uses persisted first-observed fallback rather than per-call mtime.
- Put/Update only import durable local bytes and Stage; they do not call Source, Prepare, cloud write or Confirm. Identical Flush retries reuse accepted bytes/generation. Distinct concurrent writes capture expected generation before import and return ErrGenerationChanged if another generation was accepted during copying. Accepted writes remain queued, with accurate returned size. Store handles 10 MiB Docx admission; ordinary files are streamed.
- New local `.md` names classify Docx; existing ordinary `.md` remains KindFile. New local paths are literal, so `%2F` is not decoded to a separator. Cloud title projection and conflict resolution use NFC/case-fold, reversible percent/reserved/control/trailing-character encoding, stable token SHA-256 suffixes (8, then 16, then full hash if necessary). Once persisted, mappings do not rename themselves when a collision disappears.
- BeginManagedRename runs before Flush, ensures a missing source entry for VFS's no-object cache branch, then freezes scheduling. Tokenless new nonreplacement rename records final-kind intent through controller ConfigureNamespaceKind while frozen; committed bound resources retain kind. Cross-kind temporary replacement retains destination EntryID/token/kind. RenameManaged seals latest durable Flush generations, commits, returns exact-size object; directories return `(nil,nil)` for T06's directory publication path. Finish happens only after VFS cache/node publication. No cloud Remove/Move occurs.
- CommittedError implements Committed() bool and preserves wrapped causes. Any postcommit reconciliation failure is distinguishable and must not Abort. ReplayManagedNamespace aborts only prepared/sealed freezes while retaining accepted Flush bytes; committed paths must execute the supplied cache reconciliation callback before Finish. Constructor never auto-finishes committed journals.
- Mkdir/Rmdir/Remove use Store namespace journals. Root deletion is denied; Rmdir checks emptiness and rechecks after Seal; delete materializes readable evidence first. Queued local edit deletion saves a durable conflict, while active/unknown deletion returns ErrDeleteConflict joined with store.ErrBusy and preserves its original verification journal. An edit accepted during delete materialization is detected after Seal and becomes conflict instead of being tombstoned. Tombstones retain Store recovery data.
- Default local-only basename patterns: `.DS_Store`, `Thumbs.db`, `*.swp`, `*.swo`, `.~*`; no blanket `.tmp` exclusion. Patterns are configurable. All writes still persist locally. Manager/engine must use ShouldSync before dispatch, including before resource creation; mapping is resolved by current EntryID so rename to an eligible final path can sync.

Fs also implements all required fs.Fs methods and local optional Move; Object implements fs.Object and stable EntryID ID(). Features advertises empty directories and Move without registry/global Fill. SHA-256 supported. Directory entries implement fs.Directory and use stable EntryID IDs.

ActivityWindow is five minutes. Targeted Size/ModTime/Open on an already-materialized file marks activity; ActiveEntries returns recent current non-tombstoned materialized IDs and does not acquire content. RefreshDirectories tracks only successfully listed directory IDs, resolves their current renamed paths, and refreshes those metadata listings without recursion or body prefetch.

## T06/manager handshake and mandatory integration boundaries

Manager must use the T06 NewManaged path. Before dirty cache reload, it invokes overlay.ReplayManagedNamespace. For each committed operation, callback reconciles/discards the nonempty source/destination cached data and metadata paths/subtrees and fsyncs directories, then overlay Finish unfreezes. If callback or Finish fails, NewManaged must fail construction and preserve the journal/freeze. Empty path means no source/destination (mkdir/delete) and must never cause root cache deletion. Prepared/sealed Abort leaves original caches and accepted local bytes intact.

Managed rename calls Begin before any source/target Flush. Flush uses overlay Update while prepared-frozen; RenameManaged seals and rejects later differing staging. VFS publishes cache/node paths before Finish, intercepting ahead of generic delete-then-Move. Directory commit returns nil object by explicit T06 agreement. Publish must execute inside TryExternalUpdate reservation; it performs only local Store CAS and object construction. Native direct mounts do not acquire these semantics automatically.

The Source is only a testing/composition seam for reads; production adapter wraps *cloud.Client and its owned observation lease. No account, credential, remote or mutation authority comes from the interface.

## Limits / native gates

No live CLI, mount driver, OS close/fsync error feedback, large-file network transfer, real remote namespace action or native direct behavior was exercised. This implementation does not claim server atomic snapshot/CAS, request causality, cloud confirmation, or published VFS cache safety without the T06/engine/manager handshakes.

Directory listing retains absent prior resources until engine performs evidence-backed deletion/conflict processing; it deliberately does not treat a successful missing row alone as a safe local deletion. Manager must apply the local-only policy before any queued network dispatch. New local writes assume known Store discovery mappings for existing visible cloud objects; unknown local paths are durable creations without synchronous network discovery. Complete backup, auth, remote mutation execution, create reconciliation, activity scheduling and recovery UI remain with their assigned owners.
