## worker 与 IPC

一个 mount 一个 worker、一份 Store/overlay/VFS。worker 完整初始化授权绑定、Store scope、managed namespace replay、full VFS cache、实际 native mount 与引擎后，才写 ready；仅 child spawned 不算 ready。VFS 使用 T06 NewManaged，预先赋给 mountlib.NewMountPoint 并直接调用 MountFn，禁止 mountlib 通用 Mount 创建另一份 VFS。macOS/Windows 使用编译入的 cmount，Linux 使用 mount2；缺失驱动或构建能力返回明确错误，不 sudo、不安装驱动。

私有 loopback tcp4 IPC 随机 32-byte 密钥、0600 key/descriptor，校验固定 Host、禁止 Origin、常数时间比较 bearer key，响应同时校验 mount/config/instance/PID。不使用 PID 杀进程；稳定 OS ownership lock 是存活依据。descriptor 的地址只能 127.0.0.1，禁止代理。历史 ownership 可通过 `readEndpointAt(root,id,configFile)` 和 `callEndpoint` 通信，不依赖可变的当前 StateDir。IPC controls 受停止 admission 与 WaitGroup 管理，Stop/Recovery 不会在控制请求仍写库时关闭 Store。

后台通过不经 shell 的独立进程实现，Windows 不传 --daemon。Unix setsid；Windows DETACHED_PROCESS/CREATE_NEW_PROCESS_GROUP、HideWindow。自动启动必须显式 enable：用户 LaunchAgent、systemd --user、Windows 当前交互用户计划任务（拒绝 SYSTEM/session 0）。disable 不粗暴结束现有 worker。没有执行真实自动启动注册。

正常安全停止暂停新本地 handle/namespace admission，允许现有 handle 关闭与 confirmed publication 排空，要求 readers/writers/reservations、VFS pending、jobs、namespace/create、publication、conflict 全部为空后 cancel/join 引擎并 unmount。超时恢复 admission，保留挂载与数据。显式 recovery/maintenance preserve-stop 允许已接受的 durable 待传/unknown/conflict 留在库中，取消并汇合控制请求；既有 engine 在 handle 关闭期间仍可能完成原有同步，随后 cancel/join 后退出。维护 lease 本身不新发起云请求。禁止提前 cancel 后在超时路径留下静默停止同步的仍挂载 worker。

## 生命周期、跨配置引用与升级接口

auth.Coordinator.AcquireWorkerStart 是与 auth lifecycle 同一稳定 OS 用户 domain 的 shared admission；AcquireLifecycle 是 exclusive。父 Start 与隐藏 worker 从开始直到持有 runtime 所有权并 ready 都参与 shared admission，避免 reauth 与新启动交错。所有公开配置写入及 SetAutostart 在任何副作用前参与同一 shared admission；auth.ProfileStore.Bind 在自身 exclusive lifecycle 下使用 privileged raw writer，不重复获取 shared。

`DefaultDomain/worker-state/SHA256(clean absolute config)` 保存稳定 runtime lock，以及每个已使用 root 的 ownership（ConfigFile、scope、Root、VFSRoot）。StateDir 修改、删除配置条目不能隐藏历史数据。Auth guard 获得所有历史引用后，先排斥新启动，再持 runtime/Store ownership 检查完整 pending、unknown、namespace、create、conflict、publication 和 VFS metadata。缺失/损坏/无法验证的配置或缓存一律 busy，不能重新绑定旧队列。Logout/unlink 严格拒绝有 pending 的共享引用。

显式 `account recover` 调用 `Service.StartRecovery`；仅已有验证绑定可以进入，不新建 App，停止关联 worker，保留所有历史 Store/cache 队列并持冻结 lease。成功必须复核同 brand/AppID/UID 与 scope；身份不同使 registry disabled，旧数据不会改绑。新 worker 在同身份/scope 复核后仅对 credential blocked/paused job 调用权威 Store.ResumeJob，unknown 始终仅允许 readback 验证。

`WithQuiescence(ctx,fn func(context.Context)error)` 为 T11 提供当前配置的迁移冻结；持 global exclusive、config manager lock、所有当前及历史 runtime ownership，通过 VFS 离线检查才运行 callback。callback 不允许 manager 配置重入。跨配置 installation lease 由 T12 owner 独立新文件实现，所需历史 IPC/shared-writer helpers 已交 0080b0025；此报告不声称其新代码已在本分支集成。

## 信任与真实调用边界

每次 cloud RPC 都调用 auth Status 验证实际保存的 CLI identity，并比对捕获的身份 hash；Engine 再用便宜的 Resolve 检查本地 registry。纯缓存本地编辑可继续，云操作被身份错误阻止。检查不能约束用户独立启动的官方 CLI，也不消除最后一次验证之后的外部竞态。

所有托管写操作通过 Cloud.CheckMutation 验证固定 official1.0.99 的五平台 executable SHA256；未知字节只允许经身份验证的读操作，写前 ErrNotDispatched、可恢复暂停，不接受用户 bool/env/可编辑 manifest 授权。Docx 操作另有 live XML protocol grant。实际官方 VCS 是 8d8357d39dd15ac5e9aa815d4ab2639d56bd3239；原先阅读的 1bfd source 经父 agent 对关键协议范围比较确认等价。live API 证据来自 macOS arm64，其他平台仅同版本/源码/官方 artifact 身份验证，不声称 native 运行证明。

签名注入 seam 是 manager.ReleaseCLIArtifactSHA256 和 ReleaseCLIUpstreamSHA256，默认空。只有 compiled upstream 等于固定官方当前平台 raw hash，实际 artifact 等于 compiled post-sign hash 才接受。打包流程 raw verify -> sign CLI -> hash -> compile app -X -> sign app；本任务未执行签名。
