# T07 同步引擎实施记录

模块：internal/bridge/sync，包名 syncer。主要代码提交 a21143469、7e4d7e144、6a2f0af38、9b12f4a2f、35dc5eb6e；集成分支有对应 cherry-pick 提交。此记录区分模块验证和原生/在线验收，不代表发布完成。

## 已实现行为

- 每 entry 串行，后台作业每秒调度、活动文件默认 5 秒刷新、已访问目录默认 30 秒刷新；网络/限流准备失败带退避，不清除本地输入。
- Docx 采用最新读取、三方合并、写前重读、逐项持久计划、单次局部 RPC、完整回读和上下文核验。每次操作后重新映射真实块 ID；新插入链等待回读取得锚点，绝不猜 ID。
- 不明确的操作先核验已观察到的效果。不能唯一核验则保留 awaiting_verification，不因回读旧值重发。显式人工合并先保存草稿、复核代次/修订与内容，再原子建立新的远端基线；已支持的无锚点正文可以在用户明确确认后逐块替换，保留文档 Token。未知富内容、未知列表结构仍不会被整篇覆盖。
- 普通文件在覆盖前持久保护远端下载观测，按原 Token 流式上传，回读比较捕获的 SHA/大小。显示编码后的本地名字不会用于改写原始云端文件名；命名空间确认按稳定 entry/token 更新原始云端名称。
- 新资源在 RPC 前保存唯一临时名和输入；不明确创建按完整父目录、临时名、类型和内容核验，零/多匹配均不盲目创建第二份。最后改名也有持久派发/核验阶段。
- 本机接受与云端确认分离；G1 完成不覆盖 G2 保存。VFS 忙时保留持久 publication，空闲后通过管理器发布屏障提交。
- 命名空间云端意图按持久顺序执行；删除前保存可取得内容，远端文件夹再次完整列举为非空时拒绝删除。检查后的并发窗口仍存在。
- 身份检查覆盖引擎与 Cloud 调用。CheckMutation 可阻止所有不受信任 CLI 写操作。ErrNotDispatched 只表示守卫在子进程启动前拒绝，区别于可能已提交的未知结果；前者保留证明后可安全重新准备。
- 仅隐式崩溃在无计划、无创建 journal 的读取准备阶段，才允许在新读取后继续准备。已派发计划、创建未知和显式 MarkUnknown 不会重置成可重发队列。

## 关键接口

New(Dependencies,Options)；Engine.Run、SyncEntry、RefreshEntry、Retry、Resolve、RefreshConflict。Dependencies 提供 Store、生产 Cloud 或测试 Source、Publisher，以及 CheckIdentity、OnConflict、LocalOnly、ShouldSync、ActiveEntries、RefreshDirectories。Publisher 必须由 manager 连接 VFS.TryExternalUpdate 与 overlay.Publish。

RefreshConflict 会更新输入代次和可取得的云端快照并保留草稿；网络错误同时返回保留的本地/云端视图，调用者应标记云端来源过期。Resolve 始终重新核验，不把旧 diff 当写入授权。

## 保留边界

默认普通空文件写入能力尚未取得明确服务端证明，因此保留本地并标记 empty_file_unsupported；非空后会重新调度。已有可信空文件读取不冒充失败。

观察下载不是服务器当前版本、CAS 或因果确认。写前检查和本机锁不能消除网页/外部 CLI 的检查后竞态。默认不自动重放不明确 mutation，不承诺任意历史或 exactly-once。Native/live 故障和三平台实际安装/挂载尚需独立验收。

实施调整：新 Docx 在唯一临时资源创建时提交已经完整白名单编码的正文，再核验并改最终标题；不先造空文档再经历一串补丁。这仅用于创建新 Token，已有文档绝不以整篇覆盖兜底。普通新文件同样提交真实输入。调整减少半成品和创建后的歧义，已通过完整离线集成夹具；真实新建正文路线仍在在线验收范围内。
