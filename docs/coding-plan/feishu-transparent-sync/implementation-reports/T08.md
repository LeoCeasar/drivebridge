## Ownership and lifecycle behavior

The global private registry is `<DefaultDomain>/auth/registry.json`. Auth roots are `auth/identities/<UUID>/lark`; temporary registration roots are `auth/enrollments/<UUID>/lark`. Neither references, registry, nor credential locks depend on configurable StateDir/Bridge config paths. Profile configs hold only canonical authRef/hash. Same AppID+OpenID reuses one record/root; distinct identities cannot share a record/root. `Link` adds an independently reverified same-identity profile reference without another login. Cross-config references include a private ConfigFile locator so the manager can inspect/freeze their workers and durable pending data.

Credential lock files are user-private and hashed; order is shared enrollment gate -> exclusive AppID -> optional exclusive AppID+OpenID. Unknown-AppID registration takes the gate exclusively. Brand does not split actual CLI credential locks. Each typed runner child holds these real OS file locks through cancellation/reap. A separate global lifecycle lease serializes retained authorization and reference changes across configs.

Start runs one retained registration/user-auth child through existing typed larkcli methods. The child context belongs to the Service and a 10-minute local deadline, not the initial request context. Registration has unknown server ExpiresAt, with LocalDeadline disclosed separately. App configuration completes with ErrUserMissing and never binds a logged-in profile. User auth must exit successfully, have required granted scopes, pass independent saved-config/identity verification, and match any old identity hash before binding. Complete waits the same retained child; repeated Complete is idempotent. Cancellation, service shutdown and local timeout reap before releasing the lifecycle/freeze leases and persist unknown state. Pending/unknown auth blocks the affected AppID's old Resolve/Status/Link until explicit reconciliation.

Canonical adoption renames the entire CLI-owned directory on the same filesystem; it never reads/copies token or AppSecret values. A canonical-ref intent is persisted before rename so a crash between rename and registry/profile binding can be reconciled. Existing canonical root reuse is separately verified; duplicate temporary roots are retained rather than deleting CLI credentials. Registry writes use private temp + fsync + atomic replace + directory sync. Future schema, malformed refs/duplicate identities/reference mismatches fail closed.

Reconcile is explicit current-state verification after unknown/restart, never a replay of registration or login. A valid saved application with an explicitly unavailable user can advance to app_ready for a subsequent fresh user authorization; network/protocol uncertainty remains unknown. Successfully verified identity/scopes can finish the durable binding. If configuration cannot be inspected, the operation remains unknown rather than blindly creating another app. Registration retries/discard of such an uninspectable remote app are deliberately not automatic.

## Required manager guard protocol

The guard receives every persisted reference affected by the AppID, including different users, brands and Bridge config paths. It MUST first stop/freeze their worker admission and config lifecycle changes, then inspect mounted use and all pending/unknown/conflict/recovery jobs. It must hold that freeze until the returned release callback runs. Missing/stale/unreadable config, unresponsive worker or unprovable pending state is busy; checking only a momentary status is insufficient. Nil/typed-nil guard or nil release fails closed whenever references exist. Unlink is guarded as well, so pending data cannot lose its profile credential reference. It clears only the caller's reference, retains canonical roots/identity metadata, and never calls CLI logout.

Logout rechecks exact current identity after the guard, disables shared product binding before invoking the official command, and leaves every profile/reference/recovery record intact. Unknown or completed logout is never automatically replayed; explicit same-identity authorization reenables the binding. The source-backed CLI argv is exactly `auth logout --json`; a fully bound managed runner holds AppID+OpenID locks. Its bare `{ok,loggedOut,reason}` output is operation-specific, not a business envelope. CLI remote revoke/removal is best effort, so exit0/local logged-out config is not proof of complete remote revocation.

`config.ResolveAuthRoot` remains unchanged in behavior for old T01 tests and is explicitly deprecated/legacy-only. Production managed wiring MUST use Service.Resolve/ManagedRunner. No silent state-local credential migration occurs. Managers must supply a serialized ProfileStore adapter when other config writers exist; FileProfiles is documented for one writer. Executable resolution to an absolute path belongs to the manager; this service accepts an explicitly supplied executable and does not discover shell profiles.
