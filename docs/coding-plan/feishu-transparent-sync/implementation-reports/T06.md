## Delivered contracts

- `vfs.NewManaged(ctx, f, opt) (*VFS,error)` enables admission and managed full-cache durability **before cache reload**. It forces full cache and disables handle caching, rejects an already-active filesystem/cache identity, and propagates recovery/cache construction errors. The supplied filesystem must be the worker's local acceptance overlay (or equivalent local test backend), not a directly uploading cloud backend. Native `New` continues its original path/reuse behavior; it never reuses an active managed pointer.
- `EnableManagedSync()` remains the specified compatibility entry point for unused, unshared full-cache instances. It leaves reused/native-used/in-use instances disabled; `ManagedSyncEnabled()` is the query. Worker composition must use NewManaged because late enable cannot protect prior startup replay.
- `TryExternalUpdate(ctx,path,commit)` reserves before clean-cache checks, rejects admitted unread readers/writers, invalidates only idle clean cache, invokes the prepared local commit without the manager mutex, updates existing File object/size without replacing its inode/Sys identity, marks the directory stale, then releases. Cancellation after successful commit does not skip node publication. Callback remains contractually local CAS/metadata only, without network, VFS recursion or large copies.
- `ManagedMaterializer.MaterializeManaged(ctx,path)(fs.Object,error)` and `File.MaterializeManaged`/`vfs.MaterializeNode` provide target-only fallible projection sizing. Dir.Stat and File.Open plus mount2/cmount attribute paths propagate failure before reporting size. ReadDirAll remains metadata-only; cmount omits authoritative readdir-plus stat for unknown managed projections instead of fetching every body.
- `ManagedRenamer` retains exact Begin/Rename/Finish/Abort signatures. Post-commit errors are recognized through optional `Committed() bool`; errors produced after local publication/Finish failure implement that convention. Directory success uses `(nil,nil)`; file success requires a nonnil object.
- `ManagedNamespaceReplayer.ReplayManagedNamespace(ctx,reconcile func(src,dst string)error)error` is coordinated with T05. Cache construction invokes it **before reload**. Overlay aborts prepared/sealed transactions and calls reconcile only for committed snapshots, then Finish. Reconcile removes only committed source/destination cached paths/subtrees, syncs surviving parents, rejects root/traversal/absolute/volume paths and symlink paths, and propagates errors. A failed callback/Finish leaves the overlay journal frozen; constructor fails.
- T09 stop/guard seams: `PauseManagedAdmission()(resume func(),error)` blocks new opens/materialization/namespace mutations but permits external publication to drain confirmed results; existing handles may flush/close. `ManagedActivity()(readers,writers,reservations int)`, `ManagedCachePending()bool`, and `ManagedCachePaths()(dataRoot,metaRoot string)` expose local activity. Stop must join the engine before final unmount. `vfscache.ManagedMetadataPending(dataRoot,metaRoot)(bool,error)` reads offline state under the manager's per-mount lock: Dirty, mutation > staged, orphan data, size mismatch or interrupted metadata temp is pending; corrupt/symlink/invalid-sequence metadata fails closed. Paths should be persisted from the API rather than reconstructing cache encoding.

## Admission, rename and durability

`managedState` holds only short mutex-protected token/reservation operations. Managed Handle wrappers transfer admission at construction and release exactly once after Close/Release teardown, including unread readers and directory handles. Repeated Flush retains admission. Failed construction releases its token. Native handles remain their concrete existing types. Namespace create/mkdir/remove/rename and recursive removal participate; subtree removal reserves the whole subtree. Renames migrate descendant token paths while stable tokens, inodes and adapter references survive.

Managed rename branches before generic Move/DirMove, including source o=nil: reserve source/destination → Begin/freeze → synchronously Flush cached source/destination subtrees → Rename/Seal/Commit → cache/node publication → Finish. Active source writers and active destination handles are rejected. Source readers can remain open. No generic target Remove executes. Before-commit failure calls Abort. Committed failure never calls Abort and keeps the path reservation frozen for restart recovery. Current real journal/freeze semantics belong to T05/T03; VFS barriers use a local structural fake, not a second store or network implementation.

`Cache.InvalidateClean` holds Cache→writeback→Item inspection order using the new `WriteBack.WithIdle` seam. Dirty, opens, pending accesses/reset/close/grace and queued/running stores are rejected atomically; removal errors preserve the item mapping for retry. Running stores are not canceled to manufacture idleness.

Managed Item tracks persisted `MutationSeq`, `DurableSeq`, `StagedSeq` (omitted from native zero-valued JSON). A per-item snapshot mutex covers user WriteAt/Truncate/Open, downloader non-overwrite writes, and the complete managed fsync/local Stage snapshot. Missing ranges are fetched before taking that mutex, avoiding downloader-wait recursion. Flush/Sync/ordinary Close perform data fsync, data-directory sync, atomic same-directory metadata temp write/fsync/close/replace and ancestor directory sync, then synchronous overlay Put/Update while mutation exclusion remains held. Clean/staged sequence is persisted only after local acceptance. Repeated unchanged Flush does not Stage again; later mutations remain Dirty. Managed close does not enqueue generic asynchronous cloud writeback. Existing native branches remain unchanged.

Recovery temp files are excluded from managed item reload scanning and retained; offline guard treats an interrupted temp as pending. There is no automatic inference of an interrupted temp's intended target, nor a claim of hardware power-loss proof. Full recovery source of truth is the durable overlay blob/journal plus valid cache checkpoints.
