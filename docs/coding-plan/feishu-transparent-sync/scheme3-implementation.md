# 方案三实施计划

> 执行方式：使用 writing-plans / executing-plans，沿用用户授权的多 agent 分工；不创建额外 worktree，不加入逐块审核或重复全仓测试。当前用户已确认详细方案并要求开始实施，无需再次确认计划。

目标：将可读文档投影和可写能力分开，补齐真实手册的正文、表格、图片；新增支持范围内的反向差异，保持现有逐步回读、两端基线和未知结果保护。

依据：[scheme3-design.html](scheme3-design.html)。现有未跟踪设计文件须保留；真实文档原始数据只在忽略目录 / Downloads，不提交账号或用户文档。

## 接口与责任

- 转换模块负责 `model.DocAsset{Token, Name, Path, MIME string}`；`DocView`、`DocSidecar` 增加 `ProjectionVersion int`、`Assets []DocAsset`，`Block` 增加必要的投影信息。默认新解码使用版本 2；`markdown.Options.ProjectionVersion=1` 保留原占位和原哈希行为，供旧侧车读取。
- 资源引用使用 `.drivebridge-assets/<sha256(token)>.<safe image extension>`，不含账号凭据、块 ID 或用户绝对路径。资源在每个文档同级的隐藏虚拟目录解析；图片写入首版关闭。
- 转换模块产出 `PlanStepWithBase(baseLocal, local []byte, baseRemote, remote model.DocView)` 与必要的显式合并对应接口。变更全篇解析后再规划；不支持结构或定位歧义返回完整草稿与零操作。嵌套段落操作的哈希 / 验证要与读回一致，不能偷偷整体替换复杂表格。
- 素材传输负责 `cloud.Client.OpenDocMedia(ctx, token) (io.ReadCloser,error)`，使用托管 runner、受控临时目录、相对 CLI 输出路径；关闭时释放临时文件。复用账号锁，校验资源和结果，失败不提供半文件。
- 虚拟资源模块通过可选 `DocMediaSource` 接口调用 `OpenDocMedia`。复用文档侧车原始资源引用，支持资源目录 List / NewObject / Open；不可写、不可删、不可上传成普通文件。资源实体可由 VFS 缓存，不能绕过既有清理和脏缓存保护。
- 同步集成负责保存新侧车、按旧侧车版本读取旧投影、传入原始远端基线，以及回读后逐次重新映射。后来的本地代次不得被旧结果覆盖。

## 必须保留的边界

图片新增替换、表格结构增删、任意富文本样式重建不默认开放。旧版本基线、未上传修改和冲突不能因重新投影而清空。版本参数不是原子条件写；UNKNOWN 不自动重放。
