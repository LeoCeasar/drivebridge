# DriveBridge 桌面常驻客户端：调研与需求记录

2026-11-10；本文保留最初调研记录。用户随后要求开始实现，实施范围采用已推荐的托盘＋浏览器方案，见 development.md 和 implementation-status.md。用户要求：像 Google Drive 一样后台自动运行，在状态栏显示同步状态，并能打开管理界面。

## 已核对的实现事实

- `cmd/feishu/commands.go` 已有后台启动、停止、状态、登录自启动、上传状态和重试命令；配置和后台通过 Manager 共享。
- `internal/bridge/platform/process_*.go` 已有脱离终端启动进程的实现；Windows 隐藏后台进程窗口。
- `cmd/feishu/gui.go` 启动受保护的本机 UI Host 并打开浏览器，但首次启动 UI Host 的命令会留在前台。需要提取可复用的启动/关闭生命周期，不能由桌面壳调用后遗留可见终端。
- `internal/bridge/ui` 已有每用户配置、挂载和冲突合并界面。桌面壳只能通过 Manager/受保护 IPC 使用状态及控制操作，不直接打开运行中 worker 的数据库。
- 当前自启动围绕每个挂载注册；macOS KeepAlive=false，Linux Restart=no，不能把现有机制描述为完整的桌面崩溃恢复监督器。
- 代码库当前 Go 最低版本为 1.25，没有托盘依赖，也没有独立桌面应用入口。

## 推荐的共同架构（实施者建议，未视作用户已确认选型）

一个当前 OS 用户的桌面实例，负责托盘、UI Host、通知和已启用挂载的恢复；挂载 worker 继续独立运行，复用现有配置、凭据、存储和同步引擎。CLI 保留独立使用方式。关闭页面/窗口只隐藏管理界面，后台同步继续运行。

桌面程序通过现有 Manager 启动/停止/查询挂载，所有操作使用稳定 MountID。重复打开 App 唤醒已有实例；worker 重复启动依旧由现有身份握手和互斥保护拒绝。不能只依赖 PID 或进程名称判断归属。

登录系统后启动桌面实例，不在用户登录前冒用其他账号启动。桌面模式与既有 per-mount 自启动迁移需先保存原状态、停止重复监督、验证新入口；纯 CLI 用户保留原模式。桌面启动仅恢复明确启用的挂载，认证过期或身份不符时显示待处理，不能循环登录、切换账号或重放结果未知的上传。

状态按真实 worker 状态和持久队列聚合。建议优先显示需要授权/错误、冲突、离线、同步中、已同步/未挂载；详情保留每个挂载的独立状态、待上传量、未知结果和本机发布等待。失联、仍有未确认/待发布任务或者无法读取状态时，不显示全部已同步。初版不承诺未经测量的字节百分比。

重启采用退避和次数限制；显式停止、用户退出、升级 lease 期间禁止自动拉起。升级协调同时纳入桌面实例/UI Host，避免它们持有安装文件、访问旧 schema 或重启 worker。安装过程中不得清理待上传、未知结果、冲突或恢复数据。

## 用户操作目标

1. 双击安装后的 App，出现托盘；首次未配置时打开配置页面。
2. 用户自己的飞书授权、文件夹映射、挂载位置仍保存在自己的配置中，不写入开发机环境或二进制。
3. 托盘可查看汇总/每挂载状态，打开本地目录、管理界面、冲突列表和日志，安全启动/停止挂载，管理登录自启动。
4. 关闭管理界面继续同步。只退出托盘与停止全部同步应有清晰、不同的操作含义；停止超时或存在打开句柄时保留数据，并显示结果，不直接 kill。
5. 无桌面或 Linux 桌面缺少托盘能力时，CLI 和本机管理页仍可使用，不能因此阻止同步。Linux 图标可见性需按桌面环境实测。

## 桌面壳的选项与待确认项

**待用户选择：管理页是浏览器页面，还是独立 App 窗口。**

- 托盘 + 浏览器：建议作为最小增量。可使用 Go systray；已有界面直接复用，新增依赖聚焦托盘和打包。macOS 交付真正的 `.app` 菜单栏程序，Windows 提供无控制台桌面入口，Linux 提供 desktop entry。具体 systray 版本须在实现前固定、检查许可证并做三个平台的窄验证。
- 托盘 + 独立窗口：可评估 Wails/系统 WebView，复用已有前端资源，但需要额外验证窗口生命周期、受保护 UI 会话、导航及外链规则、各平台运行时和打包；不能把现有 Go/HTTP 接入直接当作 WebView 已兼容的证据。当前 Wails 官方文档列出 Go 1.26 要求，与本项目 Go 1.25 有差异，选型前需核对拟锁定的具体版本或采用隔离桌面模块。

无论哪种，纯 CLI 产物不强制链接托盘/WebView；不采用通用 Rclone RC 或无认证控制端口来绕开现有 Manager。

## 拟分块落地与验证

- 桌面生命周期：单实例、UI Host 复用、现有挂载连接和状态聚合。小范围测试覆盖并发重复启动、worker 失联、无配置、待发布/未知结果不能误报成功。
- 托盘及动作：图标/菜单、打开目录/管理/冲突、通知去重。动作调用现有接口；不对用户输入执行 shell。每平台进行一次真实桌面交互验证。
- 自启动和恢复：桌面与 CLI 两种监督方式协调、停止意图持久化、网络/睡眠恢复与重启退避、升级期间冻结。测试只恢复显式启用挂载，拒绝旧账号数据误绑定。
- 平台交付：macOS `.app` 和签名，Windows 桌面 EXE/快捷方式，Linux desktop entry/桌面会话自启动；保留 CLI 安装路径。原生安装、自启动与升级必须有真实证据。

按用户要求，单元仅做受影响范围测试，集成块结束后执行一次整体验证，不增加逐项重复审核。
