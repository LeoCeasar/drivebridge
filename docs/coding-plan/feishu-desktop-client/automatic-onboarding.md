# 授权自动接续与默认账号盘

2026-11-11，基于 `2fd85f1fe`，按用户要求省略授权完成确认、默认不选择挂载目录。

## 用户流程

用户添加并授权自己的飞书账号，在官方页面完成必要的登录及权限同意。DriveBridge 后台自动等待官方 CLI 结果并核验身份。应用配置和用户授权属于两个真实授权阶段：若首阶段只完成应用配置，后台自动发起用户授权并更新页面链接，不把应用配置误判为用户已登录。官方页面的用户同意和身份验证仍须本人完成。

用户授权成功后，后台自动打开应用独立登录窗口；网页登录完成后自动发现目录、创建或复用每账号唯一账号盘并启动挂载。网页登录阶段与自动核验监视器使用一致的5分钟等待窗口，超时明确结束进度并保留可重试入口。成功必须同时满足身份有效、本次入口扫描完成、真实挂载正在运行，不能只凭目录快照完整就显示成功。失败保留已有配置、凭据、队列及恢复数据。正常流程无需点击“完成授权”、手动建 remote 或选择挂载路径。

## 生命周期与接口

- `Manager.StartAutomaticLogin(ctx, profileID, recovery)` 返回首个官方 flow；后台生命周期独立于发起请求，页面关闭不取消授权接续。
- `Manager.AutomaticLoginStatus(ctx, originalFlowID)` 仅返回状态。原始跟踪ID不变，`flow` 更新为当前实际授权阶段；查询不能触发登录或挂载。
- 同账号在途请求复用同一任务；失败可重新发起。Manager 退出先停止接收并取消、等待接续与登录监视任务，然后关闭会话组件。
- `POST /api/auth/start` 返回 `auto_complete:true`；`POST /api/auth/status` 接受 `flow_id`，沿用本机会话、Origin、CSRF和参数校验。
- 页面只持久化进度ID与profileID，不保存授权URL或凭据；重开同一本机管理服务的页面可恢复查询。失效任务明确结束，不用陈旧成功状态代替新检查。
- 旧 `/api/auth/complete` 接口保留兼容。新管理页不调用它；异常时的检查按钮只读取进度。

## 默认挂载与平台差异

每账号自动分配当前系统用户目录下 `DriveBridge/<profileID>`。路径由应用决定且随配置复用；不会要求用户选目录或盘符，也不会将本机路径写死在发行包里。自定义单目录挂载表单放入默认折叠的高级设置，网页登录手动复核也放入“登录遇到问题”。

macOS/Linux 使用存在且为空的挂载目标。Windows WinFsp 目录挂载要求最终目标不存在，因此仅准备父目录；worker 启动重检沿用相同平台规则。之前代码在两个位置都创建了 Windows 最终目录，会导致“mountpoint path already exists”，本轮已修复。旧 Windows 已存在目标不会被删除或迁移，即使为空也保留并拒绝覆盖。

## 当前交付边界

macOS 原生 WKWebView 组件已存在。Windows/Linux 的原生网页登录组件尚未接入，仍返回明确 unsupported；本轮共用自动接续和挂载路径策略不能替代该组件。因此当前不能声称 Windows 用户已经能完整执行“首次授权→网页登录→自动挂载”。Windows 用户流程的目标一致，底层路径准备按平台适配。
