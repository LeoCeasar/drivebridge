# 文件删除同步与本地版本恢复

适用范围：飞书普通文件（含 Markdown）、现有 Docx 投影，以及当前挂载和已移除挂载的冲突记录。目录递归删除仍遵守原有空目录检查；本次没有增加删除整棵云端目录树的能力。

## 用户行为

| 情况 | 行为 |
| --- | --- |
| 本地显式删除，存在尚未派发的上传或历史冲突 | 记录删除意图，取消旧上传并结清相关冲突，随后删除云端文件 |
| 文件上传结果未知、命名空间操作尚未结清或文件仍打开 | 保留正文与日志，拒绝或延后删除，不能把未知结果当成功 |
| 云端文件从完整父目录列表中消失，本地无修改 | 移除本地占位、缓存节点及可见状态，不生成合并任务 |
| 云端文件消失，本地有修改或历史冲突 | 保留正文与草稿，进入 `remote_deleted` 冲突 |
| 选择“保留本地版本并重新上传” | 保持本地路径，以本地正文或用户编辑结果重建云端文件，上传后独立回读确认 |
| 选择“跟随云端删除”并确认 | 移除本地可见文件，结清待上传任务及该文件的冲突记录，保留恢复资料 |
| 旧版留下的“删除待上传文件”冲突，文件从未关联云端 | 标为 `local_delete_pending`，可选择保留本地并上传，或确认本地删除、取消上传；不伪装成云端删除 |

重建文件会获得新的飞书文件标识，不能恢复原标识所关联的历史或分享链接。原始云端文件名会保留，不采用本地转义名称或同名消歧后缀。

## 检测与并发边界

- 只使用成功、完成分页的父目录清单证明资源已不在该目录；下载失败、超时和权限错误本身不证明删除。界面因此表述为“已删除或已移出同步目录”。
- 目录扫描在请求前捕获本地条目；提交时同时校验修改代次、路径、Token、本地基线和云端基线，避免把扫描期间新创建的文件误当成删除。
- 本地可见状态通过 `VFS.TryExternalReconcile` 更新，沿用已打开文件、写入和正文缓存的保护。网络请求在此事务回调之外执行；目录锁不与 VFS 回调交叉持有。
- 用户提交决定时再次读取父目录。旧文件重新出现、同名替代文件出现或查询失败时，保留本地内容并要求重新复核。
- 上传超时、创建结果未知和已派发删除的结果未知日志不能被此流程丢弃。只有未派发的删除任务，才能通过已确认的目录缺失直接结清。
- 同路径的新建云端文件需等待前序删除结清，避免绕过尚未确认的删除任务。
- 跟随云端删除时，旧标识保留在恢复记录，当前墓碑解除 Token 绑定。之后云端恢复同一文件，可以重新显示为新占位并按需获取最新正文；本地主动删除的墓碑仍保留绑定，阻止未结清的云端列表复活旧文件。

## 已移除挂载

移除挂载仍停止自动同步。显式打开冲突时，可以通过身份校验后的只读客户端更新云端状态，不启动挂载或上传。

“跟随云端删除”可以在停用状态结清本地记录；“保留本地版本”保存为待创建任务，之后仍需用户恢复并启动该挂载。普通状态轮询不会为归档挂载自动联网扫描或重新上传。

对于从未上传的旧本地删除记录，仅在无 Token、无本地/云端基线、日志能证明没有未知云端操作时提供本地决定。复核与取消上传不需要认证或联网，但仍校验 Store 所属账号/挂载 scope。复核本身不会丢弃数据；必须由用户明确选择。结果未知的创建或上传仍保留并阻止结清。

## 接口

`ResolveRequest.action` 新增两个可选值：`restore_local`、`accept_delete`。删除冲突必须明确选择其一；普通文本合并保持原有请求格式。

- `restore_local` 可携带 UTF-8 编辑结果；未携带正文时保留本地原始字节，支持二进制文件。
- `accept_delete` 不携带合并正文，不会用空内容覆盖已有草稿。
- 两种决定都要求捕获的本地代次与云端删除标记匹配。

CLI 同步提供 `feishu conflict resolve ID --action restore_local|accept_delete`，沿用 `--expected-generation` 和 `--expected-remote-revision`；恢复时 `--file` 可选，跟随删除不能同时传入文件。

## 验证

- Store：清洁删除、冲突去重、跨重启恢复、过期决定拒绝、UNKNOWN 保护、前序删除与重建顺序。
- 同步引擎：本地删除优先、恢复新文件并回读、同名替代保护、云端重新出现、网络错误不误删。
- 真实 Store/Overlay/VFS/Engine 组合：待上传文件 unlink、打开句柄阻止自动删除、二进制正文恢复上传。
- 管理界面：明确决定、删除确认、二进制恢复、草稿保留、已结清记录不可再次提交。
- 停用/归档控制：只读复核、身份与 Store scope 校验、保留离线草稿、不自动启动工作进程。

这些自动化用例使用合成云端，不替代真实飞书服务的端到端删除验收。
