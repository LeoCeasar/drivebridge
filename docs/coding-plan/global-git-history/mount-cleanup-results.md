# 挂载删除与飞书精简版实施结果

验证日期：2026-11-12。本机已通过图形安装器更新为 **0.2.6 飞书版**。此次继续现有工作区，不推送代码，不改写已有验证记录。

## 删除和处理入口

- “删除挂载及缓存”会真正移除挂载配置、该实例拥有的状态与缓存；云端文件和账号 Git 历史保留。挂载点仅删除空目录，不递归删除用户目录。
- 有未上传内容、冲突、打开文件或未完成的文件系统操作时拒绝删除。历史尚未安全归档时也会阻止删除；界面提供同步任务、冲突、历史或启动同步入口。
- “暂停同步”保留配置和缓存。旧归档记录可“恢复并启动同步”，或满足清理条件后删除。账号盘删除后不会被目录扫描自动重建；重新挂载需要明确操作。
- 删除过程有持久化清理记录，配置移除后若清理中断，后台重试。相关错误向用户说明待处理原因。
- 驱动问题提供官方安装帮助，要求重新挂载的提示提供恢复和启动按钮。

## 真机结果

使用隔离测试挂载，不删除现有账号盘或用户文档：

1. 新建测试 Markdown 后立即删除挂载，命令返回 `mount_unsynced`，配置和文件内容仍在。
2. 等待上传、历史归档完成，再删除挂载成功；配置、实例状态和缓存目录均已不存在，清理前共 294,194 字节。
3. 删除后仍能从账号 Git 历史读取测试文件的原始内容；独立云端列表仍可看到该测试在线文档。
4. 已安装管理页可见“删除挂载及缓存”“恢复并启动同步”及驱动帮助入口。主账号盘仍运行，上传队列和冲突为零；其既有历史归档任务仍在后台处理，不等于所有历史任务完成。

原始证据位于本地忽略目录 `.superpowers/mount-cleanup-editions/`：`native-blocked.json`、`native-clean-status.json`、`native-result.json`、`native-retained-history.md`、`native-cloud-after-delete.json`、`main-final-status.json`。临时挂载及其配置映射已清除，云端测试文档保留供检查。

## Markdown 类型与转义边界

挂载盘中新建或复制的 `.md` 按现有策略创建飞书在线文档；已有普通 `.md` 文件保持普通文件类型，已有在线文档保持原绑定并更新文档块。真机测试的新 Markdown 在云端类型为 `docx`。这不代表通过飞书网页或通用上传工具上传 Markdown 也会自动转换。

Git 恢复保留记录中的原始字节，不额外转换，也不删除历史内容已有的反斜杠。当前在线文档投影仍使用保守的 Markdown 标点转义，原始源码中的部分 `\.`、`\:` 等仍可能出现。本轮未全局移除转义；新增测试验证标点、路径、版本号、反斜杠等连续十次转换不会累积转义。复杂新 Markdown 的不支持内容仍会阻止提交并保留本地内容，不承诺任意富文本均可无损新建。

## 构建区分和体积

新增 `drivebridge_feishu` 编译标签，只注册 Feishu/local 后端和必需产品、配置及挂载命令。普通 Go 构建和 `full` 打包继续保留完整 Rclone。原先由文件名加密列表功能间接引入的 crypt 后端也已从精简构建中分离。

Unix 打包使用 `--edition feishu|full`，Windows 使用 `-Edition feishu|full`，默认均为 `feishu`。清单记录 edition，打包前检查二进制实际版本，避免仅更改名称。认证、同步、Markdown、冲突和 Git 历史所需运行时保留。
