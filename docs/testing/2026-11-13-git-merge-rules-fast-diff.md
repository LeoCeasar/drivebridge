# Git 自动合并、转换规则与差异体验验收

日期：2026-11-13。本机 macOS arm64 开发版 0.2.14，源码 `6b4be1c80`，未签名。

## 结果

1. 后台文本合并接入可信 Git runtime 的 `merge-file`。Git 无冲突的结果自动生成飞书块操作；普通 Markdown 也使用同一文本判定。Git 输出的冲突标记不会作为上传正文。命令故障、不可表达的结构和真实文本冲突分别处理。完整普通正文改写、表格不同行并发修改、历史定位误报的自动恢复均有回归测试。
2. 默认 br 转换改由内置 JSON 定义，用户可在 config.json 同目录追加 conversion-rules.json；规则无固定条数上限，文件和单条长度有资源边界。五个字段均必填，遗漏及 null 被拒绝；代码、转义、URL 和受保护资源不受规则修改。修改规则后重启生效。字段、路径和模板见 [规则说明](../../docs/manual/markdown-conversion-rules.md)。
3. 状态观察后后台预备冲突输入与 diff；普通打开直接使用捕获的本地版本，显式刷新才核验云端。Host 最多 2 个准备线程、32 项/32 MiB，浏览器最多 24 项/16 MiB；冷启动、超限或被淘汰项目仍可能有本地计算等待，不承诺绝对零耗时。
4. 挂载、问题和冲突列表采用固定既有顺序及行复用；轮询不替换编辑正文，不重置光标、滚动、选择或已展开菜单。来源变化会使旧预备结果失效，并要求核对新来源后提交。
