# 文件独立同步、精确诊断与结构转换验证

日期：2026-11-13。范围仅为本次改变的同步排队、格式诊断及 YAML/普通表格转换。

## 实现与原因

- 手动重试及管理页面批量提交最多并发三个不同文件；同一文件请求严格串行。慢请求、冲突、格式失败不阻止其他有资格的文件提交；未知操作结果仍必须复核，不能重放。
- 格式错误从不可变任务正文捕获错误类型、行号、原文，随 journal 原子保存；状态接口不为展示错误发起云端请求。无确定来源时不编造行号。UI 使用 textContent 展示。
- 当前 `SKILL.md` 阻塞源于 YAML 头；默认规则以带正文标记的飞书 YAML 代码块保留元信息，projection 3 还原本地头部。原 projection 1/2 快照继续按原版本加载。
- 当前 `collection.md` 是人工提交任务，旧路径未使用已存在的 checkpoint-aware 表格规划。统一为安全规划器后，云端未变的普通表格可改变行列；复杂资源、合并单元格和并发变更仍保持保护。
- 默认 JSON 新增 `yaml-front-matter` 与 `plain-table-resize` 结构策略；用户旧配置自动补入，不覆盖已有字符串替换规则。结构策略不接受任意删除或不安全目标。

## 验证结果

- Markdown、store、sync、manager、UI 五个受影响 Go 包全量通过。新增默认规则后同步修正 settings 测试对规则数量的预期，manager 全量重跑通过。
- Node UI：25 项通过，包含重叠批次的并发限制、慢请求、迟到响应及其他文件可操作性。
- 定向 race：Markdown、sync、manager 并发边界通过；store 诊断持久化、重启/恢复和未知 journal 保护通过。macOS 链接器有已有 LC_DYSYMTAB warning，无 race 报告。
- Windows amd64：五个受影响包交叉编译通过；此项不代替 Windows 真机验证。
- 本地捕获的 collection 原始输入/云端 checkpoint：旧人工规划返回 unsupported_content；新规划返回一个可执行操作。私人正文未加入仓库测试。
- 飞书真实临时文档：YAML 上传→回读还原→修改元信息→回读及 VerifyOperation 校验通过，临时文档删除成功。实测代码块 caption 不可靠，因此识别标记放在代码正文，额外测试无 caption 回读；业务文档未用于该临时测试。
- 最终定向复核修复一个诊断边界：云端 YAML 错误不得指向不相关的本地首行；新增回归通过。

## 限制

云端中的 YAML 以代码块展示；保留第一行 DriveBridge 识别标记即可还原为本地 YAML 头。尚无唯一来源的云端结构错误只显示结构类型与原因；有证据的文本错误才显示行号。人工版本冲突仍通过已有差异块定位双方文本。此版本没有宣称任意富文本都可以无损转换。
