# 目录发现及时性修复验证

修复源码提交：`0009ff3dc3286e9c206bbdee2d3812b4adb1bc14`。macOS 与 Windows 使用同一套目录调度、存储、IPC、CLI 和管理页实现；Linux 保持代码兼容，本轮没有 Linux 原生验收或部署。

## 行为与回归

真实 Store 的测试先复现旧父目录保留 11 项、云端已经 12 项：过期读取立即返回缓存，优先请求在后台扫描的单目录边界插入，采用完整清单后通知父目录。队列限制 256 项；活动扫描每连续三个优先任务让出一次普通任务。单目录读取预算 30 秒，过期判断使用独立的成功读取时间。

定向唤醒只处理选中目录；普通扫描保留自己的周期和游标。worker 同时等待最早的持久退避期限，用户重复点击不能清除等待下限。冷目录失败不会反复在线查询；已有部分本地行的目录也能排队。自动请求合并到普通在途读取，手动在途请求至多补一次观察。

清单采用在同一事务中检查当前路径的 ID、token 和存活状态，再写入子项，覆盖读取中删除并同名重建的竞争。完整清单已采用时，即使账号目录投影或后续删除核对失败，仍发送 VFS 通知。缓存初始化不伪装成在线刷新；展开目录详情期间状态持续更新，同时保留输入和焦点。

独立审查发现的一项 Critical 和七项 Important 均在一轮修正中以失败断言复现，再验证通过；没有待处理的审查问题。
