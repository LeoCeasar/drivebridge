# Markdown 自动合并与写回兼容验证

日期：2026-11-13。实现提交：`27149937c`、`927935173`。本机应用：macOS arm64 开发版 0.2.13（未签名）。

## 行为

- 云端未变、本地修改：继续自动规划写回；支持普通表格扩行/扩列、列表后追加章节、保留已有章节的前置插入。
- 双端同时修改：仍执行三方合并与块级校验；重叠修改、无法证明安全的结构变更继续保留冲突。
- 普通 `<br>` / `<br/>` / `<br />`：段落转飞书换行；表格单元格转 `; `。大小写兼容，代码块和行内代码中的字面内容不替换。
- 无可映射飞书目标的相对链接：保留可读标题和路径文本，避免非法 URL 阻断上传。危险协议、任意 HTML 仍拒绝。
- 格式不支持：保留本地内容并标记同步阻塞，不再创建新的人工文本合并记录。
- 旧格式失败记录：仅在草稿未另改、代际及操作回执可证明安全时恢复正常后台处理。未发出任何写入的旧代际失败可让位于最新保存；不删除历史输入、不标记历史任务为已同步。
- 未知写入结果、创建记录、独立修改的合并草稿、富资源及合并单元格继续受保护。
- 本地保存路径和五分钟后台同步周期不变。

## 本机迁移观察与边界

原先两条格式失败记录已退出人工合并队列。较小文档完成写回；较大文档仍在正常后台分步上传。维护更新后任务从日志继续，而非丢弃已发出的写入。此处不宣称全部历史待上传任务已完成。

另有一条历史合并草稿与当前保存内容不同，继续保留，未自动覆盖。另有文件受到 front matter 或结构兼容限制；本次没有擅自移除元数据、扁平化受保护资源或更改文档类型来强行上传。

Windows 本次为代码编译验证，不代表 Windows 实机安装或 GUI 验收。飞书 API 缺少原子条件写入，仍依赖写前重读、操作日志及写后验证；无法保证任意并发富文本编辑都可自动合并。

原始日志、截图输入和业务文档捕获保留于本机忽略目录，不提交业务正文、授权材料或本机 IPC 密钥。
