# 删除结果恢复与父目录等待验证

## 原因

0.2.20 的 `syncNamespace` 遇到第一条失败就停止；已派发的删除任务直接返回“结果未知”，不再读取远端目录核验。这使旧测试目录的删除任务挡住了无关目录的创建。新文件找不到父目录云端 token，又被显示为 `network_or_protocol`。

## 修复行为

- 删除准备时保存原父目录的 EntryID 和远端 token。旧记录仅从与该删除操作 ID 对应的持久历史事件中恢复身份；缺少可靠证据时继续保留未知状态。
- 对原父目录完成一次有效列表查询，确认原文件 token 不在其中后，结束“从该同步目录移除”的任务。不会按文件名删除同名替代文件，也不会追踪移动到其他目录的文件再次删除。
- 核验和落库之间再次比较源条目与父目录身份，防止读取期间的身份变化。父目录被本地删除后，仍通过原 EntryID 找到其记录。
- 重叠路径、条目 ID 或远端 token 的任务保留顺序；其他任务可以继续。轮转游标跨元数据周期保存，慢任务不会永久占据队头。
- 短超时只限制目录读取，删除前的可恢复内容备份保留原来的调用时间预算。
- 新父目录未上传时显示“等待上级文件夹”；父目录就绪后重新调度未派发的子文件。删除结果仍不明确时，界面单独显示，不提供盲目重放删除的入口。
