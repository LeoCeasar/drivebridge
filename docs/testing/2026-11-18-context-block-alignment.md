# 上下文内容块定位修复验证

## 原因与修复

相同文字的段落、相同内容的两张表格可以属于不同章节和不同飞书对象。原算法在全篇发现重复内容时直接拒绝对应；纯文本回退又无法处理台账中已有列表，造成正常修改被阻塞。

修复采用有界的上下文分区：未修改且在当前范围内唯一的内容块作为顺序锚点，再处理锚点之间的范围；不再要求内容在整篇文档中唯一。真正无法区分的相邻复制、跨区移动和交换仍会保留提示。

同时保留历史快照中的云端 ID：即使两张同文表格换位后 Markdown 完全相同，也不会把另一张原表当成待修改对象。所有区域的硬歧义在回退之前检查。单元格内部仍需唯一对应，不按相同段落的序号猜测；不同单元格可利用固定表格结构定位。

新的操作校验摘要绑定写前完整快照、操作类型、目标/锚点、XML 和写前/写后摘要。回读继续检查精确目标、其他块的 ID 与原始 XML、完整非目标上下文。旧任务缺少新摘要时继续使用原来的保守校验，不清空或重放未知写入。列表项的回读摘要在其真实 ul/ol 父级内计算，避免把独立 li 片段误认为不支持的结构。

此修复直接进入共享算法，macOS/Windows 使用相同代码，不需要用户修改文档或新增转换模板配置。

- 投影版本 1/2/3 的同文表格独立修改和删除、重复子标题按上级范围定位、未修改富资源保留。
- 云端 ID 隐形交换、跨区交换伪装成替换、混合软/硬歧义与前缀插入回退、错误目标、过期/移用操作摘要均不产生错误确认。
- 单元格内相邻同文段落继续暂停，不同固定单元格/表格中的同文段落可独立确认。
- 替换/删除的未知结果保留身份约束；超时后不会重放已观察到的写入；旧上传完成不会覆盖较新的保存。
- 对齐具有共享工作预算；连续插入回溯改为线性内存，8,000 个不同块的回归上限为 32 MiB。

真实快照的离线操作回放共 7 次操作（6 次插入、1 次替换），每次回读均通过，两张未修改表格的原 ID 和 XML 完整保留。完整隔离数据库/Engine 队列回放完成第 11 代旧任务及第 13 代最新保存，共 10 次模拟写入，无真实网络调用。
