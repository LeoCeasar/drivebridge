# 文件独立同步与精确转换诊断实施计划

> **For agentic workers:** 使用 subagent-driven-development，按独立模块实施；本次仅对改变的边界做定向回归，最后合跑受影响包。

**Goal:** 一个文件待合并或转换失败时，其他文件继续提交；错误展示具体类型、行号和原文；当前两份格式阻塞使用无损、可配置的转换。

**Architecture:** 保留五分钟最新保存版本的后台同步。手动重试和批量提交采用最多三个文件的并发队列，同一文件仍串行。错误从不可变任务正文捕获并随 journal 持久化，状态展示只读本地诊断。转换规则仅处理后台副本，保护元信息、未知云端操作及历史快照。

**Tech Stack:** Go、bbolt、Git merge-file、原生 JavaScript、飞书官方 CLI XML。

**Spec:** 本轮用户的三个需求；沿用 `2026-11-13-merge-string-normalization.md` 的后台转换约束。

## 全局约束

- 保存与打开不增加云端调用；同步周期继续五分钟。
- 不将格式错误伪装为版本冲突；Git 干净合并仍需通过云端操作可表达性验证。
- 已发出但结果未知的操作先复核，绝不盲目重放。
- 同一文件待返回的旧请求不能覆盖新草稿；不同文件独立。
- 旧 projection 1/2 持久化快照不改变解码结果。

## 任务及验收

- [x] 手动重试并发、批量提交按文件排队：阻塞/冲突/慢请求与健康文件并存时，健康文件完成。
- [x] `SyncDiagnostic`、原子持久化、状态传递与 UI：只在可证明来源时显示行号；原文通过 textContent 渲染；重启后仍可显示。
- [x] YAML 元信息：默认结构化规则映射到带识别标记的 YAML 代码块；新 projection 3 还原，旧快照维持原义。保留键值、换行及所有正文。
- [x] collection 文档：先在本地逐步规划模拟定位真实失败；不把业务正文写入公共测试，不添加无依据的替换规则。
- [ ] 合跑 markdown/store/sync/manager/ui、并发回归、Windows 编译；更新安装包与本机后检查实际两项记录。

## 重点边界

同一文件超时后迟到的响应；批次重叠仍遵守全局并发上限；保存新代后旧错误不能冒充新代；模板代码中的 YAML/HTML 不被替换；未知写入 journal 不能被“重试”清空。
