# Windows 保存与同步缺口修复

用户在兼容性审核后明确要求开始修复；沿用既有本地优先、五分钟合并云端任务、待上传数据保护规则。

## 方案

保持共用 Store/Overlay/VFS 引擎。删除通过已有 checkpoint 与独立读取代保存旧句柄内容，避免 WinFsp 的删除句柄阻止自身删除；真实写入和未完成命名空间仍受保护。普通文件和空目录都要覆盖。不能通过提前删缓存、忽略提交错误或全局放开写入保护解决。

Git 使用已有 `platform.BackgroundCommand`，同时覆盖版本探测、归档及正文流读取。无须另建进程管理器。

本地 WAL 确认失败与后台归档失败分开提示；仅关闭文件时 WinFsp 不传播关闭回调错误，因此必须由应用保留本地修改、展示未完成本地确认的状态并允许安全重试。成功保存不得等待网络，也不把每次 Write 改成同步网络或强制整文件落盘。

Windows 原生验证使用无账号的合成 provider 和真实 WinFsp 挂载，运行 Win32/Go 文件操作，覆盖保存、读取代、删除和恢复；GUI 编辑器实测仍单独报告，不能拿编译或回调模拟代替。

## 取舍与验收

- 不重写同步引擎，不迁移 File Provider/Cloud Files API。
- 不用取消全部读取句柄或忽略 EBUSY 的方式隐藏删除错误。
- 明确区分真实 Windows 执行、macOS 回调模拟、交叉编译与未运行项。
- 已同步正文可删除，未完成归档的正文保留历史；读取旧代不能把文件重新放回目录。
- Git 子进程保留管道、取消与错误传播，并具备 Windows 无窗口标记。
- 本地日志失败时显示错误、保留未确认状态；恢复后可重试，不要求用户重写正文。
- 三平台共用行为不回退；先小范围测试，最后受影响模块全量和竞态检查。
