# 授权恢复与挂载状态修复

用户已确认实施会话中的方案。故障证据：凭据缺失被错误映射为 identity_changed；恢复授权持有挂载锁，状态返回 pending，按钮灰色；旧错误和静态“已授权”掩盖当前等待授权确认的状态。

## 范围与取舍
采用现有授权恢复保护机制上的渐进修复，保留身份绑定、缓存、待上传任务和跨进程锁。只改文案不能修复错误分类；重写凭据存储缺少根因证据且会扩大风险，因此不采用。官方 CLI 不修改、不绕过钥匙串、不记录原始凭据或响应正文。

## 行为
- 凭据缺失/过期返回需要重新授权，存储不可访问独立提示，核验网络故障保留可重试语义；真实 AppID/brand/OpenID 不一致仍为 identity_changed，所有未核验身份继续阻止业务操作。
- 挂载状态包含后端拥有的当前授权进度，不依赖当前标签页是否发起流程；读取进度不查询云端、不启动登录。
- 等待授权时挂载行显示原因和继续授权入口；保留禁用的挂载保护。应用登录、正在挂载、失败/过期均有明确下一步。
- 活跃流程优先于旧的挂载级账号错误；真实的逐文件失败、队列与冲突仍保留。终态以最新挂载状态为准，不把完成授权等同于云端上传完成。
- “已授权”静态标签改为“账号已绑定”，实际授权与挂载进度单独呈现。等待较久提示飞书页面的最终授权按钮；失败提供重试，重试复用安全的原身份恢复流程。
- 诊断仅保留有限的机器类型/阶段，不保留 CLI 自由文本、授权链接到磁盘、令牌或密钥。首次令牌为何消失仍需单独诊断，不声称本修复能彻底避免令牌失效。

## 验收
使用缺失凭据、存储失败、网络核验失败、真实换号、等待确认、过期、新标签页、另一账号、恢复成功等测试；执行产品 Go 测试及全部前端测试，构建 macOS 可挂载程序并用隔离预览验证页面。不主动重启或替换当前已恢复的本机应用。
