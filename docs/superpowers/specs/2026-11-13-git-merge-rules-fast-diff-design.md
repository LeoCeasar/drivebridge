# Git 自动合并、JSON 转换规则与稳定差异界面

用户明确要求继续实现四项优化；沿用已授权的分块测试、一次集成验证流程。

1. 文本合并使用已有可信 Git runtime 的 `merge-file`。成功结果进入自动写回，不再因自有段落算法的保守定位要求人工文本合并；Git 执行故障标记同步阻塞。普通 Markdown 和在线映射文档都采用这一判定。在线文档以当前远端快照为操作基准，安全规划 Git 结果；受保护的富内容/未知写入仍阻塞并给出原因，不能借 Git 成功删除资源。独立编辑的合并草稿保留。
2. 用版本化 JSON 数组声明转换规则（id、source、target、context、match）；默认覆盖简单 br 在段落/表格中的转换。允许追加精确替换规则；基于 Markdown AST 生效，排除代码、URL、转义文本，不做全文件正则替换。提供用户级 JSON 文件入口、校验和明确错误；运行时使用不可变规则集，安装包包含默认规则。
3. 发现人工冲突后后台预备本地四份正文与 diff；首次打开直接使用已捕获内容，不等待云端。以冲突输入指纹缓存并失效；限制缓存容量和并发，提交仍核验云端。显式刷新可读取云端，普通轮询不改变编辑器正文。
4. 列表顺序确定并保留已有行位置；扫描不影响选择、焦点、滚动或草稿。状态小更新不重建整个表格。固定布局与内容区域，避免进度/错误文本改变页面位置。

方案选择：复用打包 Git、现有 AST 和本机管理页。继续扩大自有文本算法无法保证与 Git 行为一致；全局字符串替换会修改代码；每次点击重新拉云端使网络延迟进入操作路径，均不采用。

验收：真实 Git 无冲突示例自动写回且不生成冲突；Git 真冲突保留；执行故障不伪报冲突；自定义 JSON 扩展生效且代码字面量不变；已预热 diff 打开不触发云端；来源变化缓存失效；重排状态输入不使界面跳动；相关包测试/race及 Windows 编译通过。本地保存与五分钟后台周期不变。
